# 现状发现

- `PROJECT.md` 明确原型入口为 `block_trading_docs/产品原型/shadcn-mobile/`，技术栈为 React、TypeScript、Tailwind CSS、shadcn/ui。
- 推荐产品文档已定义顶部栏、未读摘要、兴趣筛选、社区/商城/通知混排、负反馈、刷新/分页、离线/未登录/内容失效状态。
- 业务模块文档验收重点是类型不过度偏向、返回位置恢复、失效内容解释。
- 现有 `src/App.tsx` 已有五入口、社区卡片、商品卡片、通知和多种 shadcn/ui 组件，可在同一文件内收敛本轮推荐页改动。
- 当前推荐页缺少拼车筛选、城市切换、推荐原因、商城混排、卡片负反馈、刷新/分页反馈和离线/失效验收状态。
- 推荐页原型应继续复用当前 `Card`、`Button`、`Badge`、`Sheet`、`Dialog` 等 shadcn/ui 语义组件，避免新增只服务一次的抽象层。
- 390×844px 首屏可完整呈现顶部工具、未读摘要、筛选、重点推荐与首条信息流，底部导航未遮挡主要操作。
- 桌面态操作反馈提示限制为 398px，避免在宽视口中横跨页面。
- 干净标签页加载后浏览器错误与警告日志为空。
- 独立搜索页采用顶部返回/搜索/取消、最近搜索、热门搜索和全部/社区/商城结果切换，符合移动端搜索任务流。
- 首页分类由“凑伙”拆为“旅游”和“游戏”，列表头同步表达分类说明、匹配数量和排序方式。
- 三行订单状态轮播最终高度 158px，通知未读数独立显示在铃铛图标上。
- 第三轮反馈要求订单状态继续压缩标题区上下留白，并将“查看全部”降级为更小的辅助操作文字。
- 当前订单状态仅通过 `orderOffset` 每 3.2 秒直接换序，没有滚动位移动画；需要以固定三行视窗承载两组三行，并在每次整组上滚后无感复位。
- 关注分类当前使用“关注动态 / 关系优先”，本轮需将标题与排序文案统一恢复为“为您推荐”。
- 内容列表中的 `notice` 项会渲染“活动提醒”卡片，本轮应从推荐信息流模型和渲染分支中移除。
- 390×844 首轮实测订单卡片高度为 126px、标题 12px、三行视窗 92px，页面与 DOM 均不含“活动提醒”，“为您推荐”标题和排序共两处。
- `Button` 的尺寸变体在浏览器中将“查看全部”字号覆盖为 14px，需要使用明确的 9px 内联字号保证辅助操作层级。
- 修正后浏览器实测“查看全部”为 9px；初始第一组三条在 6.8 秒后完整切换为第二组三条，页面控制台无警告或错误。
- 刷新后首张截图恰逢浏览器样式热替换，按钮出现瞬时深色状态；不作为交付图，待下一轮稳定后覆盖首页截图。
- 第四轮要求订单状态除自动循环外还允许手动滚动；需要让手动输入优先，取消正在执行的自动动画并设置恢复等待，避免两种滚动争抢。
- 为避免设计点分散冲突，产品规划和业务实现文档需要集中维护标题层级、纵向留白、三行分组、自动节奏、手动输入、恢复规则、默认推荐文案及通知呈现边界。
- 真实滚轮输入可将订单列表从 0px 吸附到 92px，且首个 5 秒自动周期被正确跳过；但强制滚动吸附会阻止逐帧自动动画，需要仅在 1.4 秒自动动画期间临时关闭吸附并在结束或手动介入时恢复。
- 临时关闭自动动画期间的吸附后，自动循环、真实滚轮暂停、键盘手动滚动和下一周期自动恢复均通过；滚动视窗为 92px，A/B/A 轨道总高 276px。
- 最终移动截图分别固定在第一组 0px 和第二组 92px；桌面 1440×1000 下手机容器为 430×900，无横向溢出，内容列表不含活动提醒，浏览器控制台无警告或错误。
- 第五轮命名统一将首页原“旅游/游戏”筛选替换为“线下组队/线上开黑”，并与社区原“凑伙”分类合并为同一组业务值；“游戏”等词仅保留在活动内容描述中。
