# 发布生命周期兼容性审查

## 目标

以目标发布周期回看全部前置周期的实体落地兼容性：R2 审查 R1，R3 审查 R1/R2，R4 审查 R1/R2/R3。识别会造成数据迁移、历史失真、权限绕过或治理缺失的前置阻碍，不调整已确定的 R1-R4 发布范围。

## 审查关口

- [x] 建立审查准则与范围
- [x] 审查 R1 落地对 R2 的影响
- [x] 审查 R1 与 R2 对 R3 的累计影响
- [x] 审查 R1、R2、R3 对 R4 的累计影响
- [x] 汇总前置修正项、可延期项与验证结论

## 审查准则

1. 历史事实：实体是否保存发生时的区域、规则、价格、权限和责任归属快照。
2. 可扩展性：后期新增实体能否以关联表或可选字段承接，而不重写既有主实体或篡改历史。
3. 一致性：跨服务或异步链路是否具备幂等键、状态流水、失败重试和补偿边界。
4. 治理性：区域授权、审计、证据、留存和数据主体请求能否覆盖前期已产生的数据。

## 决策边界

- 本轮为分析与设计审查，不提前实施后期业务功能。
- 提出的前置项分为“必须在前一周期预埋”和“可在后一周期增量实现”。
- 本轮根据用户要求将审查结论回写项目规划和分期实体设计；发布顺序保持 R1-R4 不变。
