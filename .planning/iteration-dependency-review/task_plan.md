# 迭代周期前置依赖审查与调整

## 目标

检查 R1-R4 规划、架构、领域边界、模块与测试用例中是否将后续周期能力设为当前周期实施前置条件；将有影响的内容形成问题表，并调整正式周期规划，使每个周期在稳定契约、Stub 和功能开关边界内可以独立实施。

## 阶段

- [x] 建立审查范围、恢复现有规划上下文
- [x] 提取各周期能力、前置条件与跨文档依赖
- [x] 形成影响清单并定义消除阻碍的调整规则
- [x] 回写产品规划、系统架构、模块和测试文档
- [x] 校验链接、周期一致性与构建状态

## 审查原则

- 每一周期只依赖已在更早周期交付的稳定契约，或同周期显式交付的能力。
- 后续周期能力只能以接口预留、受控 Stub、事件信封或默认关闭的功能开关形式出现，不能成为当前周期上线、测试或业务流程的硬依赖。
- 对跨域异步流程，当前周期必须定义降级、重试和人工收口，不能等待后续自动化能力。
- 问题表中必须指明来源、受影响周期、阻碍原因和具体调整。
