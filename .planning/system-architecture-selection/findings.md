# 调研发现

## 已确认约束

- 项目使用 Spring Boot 4、Spring Cloud、Spring Embabel、MyBatis-Flex；中间件为 Nacos、Redis、RabbitMQ、MinIO；数据库设计以 Oracle 为准。
- DDD 是系统架构指导，六边形架构是模块分层指导。
- R1 需要审核链、区域 RBAC、可见性过滤、客服和事件观测；R2 增加支付、区域库存、物流、售后和关键通知；R3 增加跨区域经营、实验、数据生命周期和灾备；R4 增加封禁、反欺诈、模型治理、侵权和规模化权益。

## 架构判断

- R1 采用模块化单体部署形态，但从代码和数据访问层建立可拆分领域边界；网关、异步事件、搜索和对象存储等基础设施从首期接入。
- 支付/库存/订单/履约、审核/模型/人工、可见性/搜索/推荐、通知/客服、区域/RBAC/审计应分别拥有应用服务和仓储边界。
- 外部请求使用 REST/OpenAPI；异步业务事件使用 Outbox + RabbitMQ；订单等关键流程使用 Saga/状态机和补偿，不使用跨库强一致事务。
- R1 使用规则排序和基础搜索，R3 开始实验和区域化运营，R4 才启用个性化模型、关联反欺诈和复杂商业化自动化。
