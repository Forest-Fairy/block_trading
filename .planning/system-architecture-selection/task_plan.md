# 系统架构与技术选型

## 目标

基于趣汇 R1-R4 产品规划和跨期实体设计，形成可支撑受控内测、单区域交易、跨区域运营与规模化治理的系统架构设计和技术选型文档。

- [x] 回写正式文档、导航并完成一致性校验

## 决策原则

- R1 优先模块化单体和可独立部署边界，避免业务尚未验证时承担全量微服务运维成本。
- 交易、审核、可见性、通知和治理使用明确领域边界；跨域一致性使用 Outbox + RabbitMQ + 幂等消费，不使用分布式两阶段提交。
- Oracle 保存交易和治理事实，Redis 保存短期状态/缓存，MinIO 保存受控媒体，搜索和分析使用专用派生存储。
- 所有自动化决策必须可版本化、可审计、可人工复核和可关闭。
