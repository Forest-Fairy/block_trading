# 调研发现

## 初始基线

- 正式设计要求 R1 后台至少表达内容审核、举报、区域工单、公告、审计、权限范围、高风险审批、系统应急和受控运维；R2-R4 再按交易、区域扩张和风险案件扩展。
- 当前 `AdminConsolePage` 只有“待办/审计/权限”三个静态卡片，没有筛选、列表、详情、处置、工单流转和角色差异交互。
- 当前 `RegionManagementPage` 只有授权区域和一个加载按钮，没有区域切换、内容队列、公告与工单初版表达。
- 独立 PC 后台与移动设置页复用相同页面组件；本轮应保持共享能力和数据范围，但通过 `surface` 调整信息密度，不复制权限规则。
- 初版后台信息架构确定为：总览、审核队列、工单、审计、权限；系统管理员额外呈现受控运维和授权变更，运营管理员只读自身授权且不可修改系统配置。
- 区域工作台确定为：区域总览、区域队列、公告/工单；所有模拟操作只改变原型本地状态，并明确“服务端仍需 RBAC/二次验证”。
- 管理页面在角色或迭代变化时需要重置本地模拟状态；通过在 `App.tsx` 为移动/PC 管理页加入角色与迭代组合 key，避免上一身份的筛选或处置状态泄漏到新会话。
- PC 与移动端复用页面主体，通过稳定的指标网格、可横向滚动页签和 48rem/30rem 响应式断点调整密度；不复制业务逻辑。
- 截图复核确认 PC 总览的指标、会话条和工作重点层级清晰；区域移动工作台的授权范围、页签和状态卡片在手机壳内无遮挡。
- “查看优先队列”初版只显示提示，没有执行其命令语义；应将 Tabs 改为受控状态并直接切换至当前角色队列。
- LOOP 复验确认总览命令已切换至对应队列，系统/运营权限差异和区域授权边界保持不变；页面日志只有 Vite/React 开发提示，无原型 error 或 warning。
