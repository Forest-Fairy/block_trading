# 需求与测试对齐计划

## 目标
基于移动端原型与产品规划，形成各功能模块的需求文档和 `Rn-Tm` 排期表；再与现有功能测试用例逐项比对，补齐缺失测试或补充必要需求，并留下可追溯的对齐矩阵。

## 阶段
- [已完成] 1. 按产品文档导航链定位规划、模块文档、测试用例与原型边界。
- [已完成] 2. 提取原型与规划中的模块能力，建立需求与排期基线。
- [已完成] 3. 执行需求-测试双向比对，判断并记录差异处置。
- [已完成] 4. 回写需求文档、测试用例及导航摘要。
- [已完成] 5. 校验文档链接、编号、排期和覆盖关系。
- [已完成] 6. 将需求表拆分为按 R1-R4 的 CSV，补充风险、访问方式和层级模块列。
- [已完成] 7. 补齐测试闭环缺口，并建立逐需求覆盖评估。
- [已完成] 8. 建立接口文档先行与变更同步规则。
- [已完成] 9. 审查其他文档中的封闭状态、类型和策略字段，并补充缺失的枚举说明。

## 决策记录
- 需求文档以产品文档为基线，按 `项目文档 -> navigator.csv -> content.md` 逐层读取。
- `Rn-Tm` 采用 `R` 表示迭代周期、`T` 表示该迭代内优先级；具体映射以产品规划中的既有定义为准。
- 本次将 `T1` 定义为本周期发布阻断项，`T2` 为核心体验，`T3` 为不阻断闭环的增强项；定义已写入需求文档。
- 需求 CSV 的“访问方式”和“涉及模块”均为开发后回填列；在未实现前仅记录候选能力或目标层级，不将其视为已生效 API 契约。

## 错误记录
| 错误 | 尝试 | 处置 |
|---|---:|---|
| 无 | 0 | - |
| CSV 属性计数误判 | 1 | 改用表头与逐行字段数、Import-Csv 属性名复核，确认 CSV 完整。 |
| PowerShell 正则命令引号未闭合 | 2 | 停止该命令，改用单引号正则并限定业务开发文档、数据库设计目录；结构化反查改用逐行解析。 |
| PowerShell 反引号导致字典反查解析失败 | 1 | 改为不拼接 Markdown 反引号的纯字符串包含检查。 |
| PowerShell 压缩校验脚本缺少 `foreach ... in` 分隔空格 | 1 | 拆分为独立校验命令并保留标准空格，核心与治理反查均通过。 |
