# 迭代周期兼容性复审与调整

## 目标

以当前 R1-R4 产品、实体、服务领域、模块 API 和系统架构为基线，逐个审查目标周期受到全部前置周期规划与设计的影响；将会阻碍当前周期规划或实施的事项列为影响矩阵，并依据矩阵调整正式周期规划。

## 阶段

- [ ] 提取当前 R1-R4、实体、领域、模块和架构的周期依赖证据
- [ ] 审查 R1 对 R2 的影响并记录阻碍/预埋项
- [ ] 审查 R1/R2 对 R3 的累计影响并记录阻碍/预埋项
- [ ] 审查 R1/R2/R3 对 R4 的累计影响并记录阻碍/预埋项
- [ ] 形成影响表，回写周期规划、实体/领域/API 设计并完成一致性校验

## 判定原则

- 某能力必须在目标周期开始前具备事实、接口、快照、幂等或治理基础时，归为前置预埋项；不等于提前开放后期用户功能。
- 若缺失会导致数据迁移、历史失真、双主状态、权限绕过、无法补偿、无法审计或无法合规处理，归为阻碍项并调整前置周期规划。
- 目标周期回看全部前置周期；例如 R4 同时审查 R1、R2、R3，不只审查 R3。
- 优先通过新增版本化事实、投影、端口和事件消除阻碍，不回写覆盖既有历史状态。
