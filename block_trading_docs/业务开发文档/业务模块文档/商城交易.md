# 业务模块文档：商城交易

## 模块目标

R1 支持趣汇自营产品从发现、加购、下单到白名单支付结果的基础闭环；R2 在同一订单与支付事实之上补齐退款、售后、完整履约和资金对账。

## 首期任务

- 建立商品分类、列表、详情、规格和库存表达。
- 实现购物车、确认订单、支付状态和订单查询。
- 游客仅预览公开商品、商品详情和交易步骤；收藏、加购、下单、支付与订单查询必须完成身份认证，拒绝时不得产生持久化事实。
- 明确自营主体、配送范围、发货时间和售后规则。
- 支持售罄、预售、限购、价格变化和支付失败状态。
- 商城筛选中的商品分类移除“全部商品”，分类和商品状态使用数组参数与复选框，支持多选和取消；价格区间与排序条件保持原有交互。
- 商品卡片主体进入商品详情页，卡片按钮统一为“去看看”；详情页对 VIP 开放加购和立即购买，对游客显示认证提示。
- 商品详情返回按钮固定在左上角，返回商城后恢复列表、分类和筛选状态。

## 验收重点

- 商品主图、价格、规格和库存同步变化。
- 下单前对价格或配送变化进行再次确认。
- 订单变化同步生成业务通知。
- 商品分类和商品状态可分别多选，选中两项时不会覆盖前一项；未勾选分类时不限制分类结果。
- 商品卡片点击详情、详情字段展示和“去看看”主操作均可在原型中验证。
- VIP 可在原型完成“详情 → 加购 → 购物车 → 确认订单 → 支付结果”；游客仅能预览且购物车、订单和支付状态均不变化。
- 商品卡片收藏与详情入口不得形成嵌套交互元素，关键交易路径控制台无 error。

## 功能接口

接口版本为 `v1`，归属 `FR-COMMERCE-R1-001`、`FR-PAYMENT-R1-001`。商品浏览允许游客；购物车、确认订单、支付和订单查询必须登录。确认订单与支付回调分别以 `Idempotency-Key` 和 `eventId` 幂等；价格快照不接受客户端覆盖。支付发起只创建服务端支付事实并返回当前订单快照，客户端不得据此显示成功；最终 `SUCCEEDED/FAILED` 必须由 HMAC-SHA256 验签的 Provider 回调写入，再由订单查询读取。生产支付适配器缺少至少 32 字符密钥时验签失败关闭。适用用例为 `R1_GUEST_001`、`R1_MALL_001`、`R1_PAYMENT_001`。

## 生产前端与交互记录

- 生产源码位于 `block_trading_client/src/App.tsx`，移动 Web 与小程序入口复用同一真实 API 交易状态机；原型静态购物车、价格、订单号和支付结果不进入生产。
- 商品卡片进入详情；游客可查看详情，但加购、确认订单和支付按钮保持禁用并明确提示登录，不产生请求或本地业务事实。
- 登录用户按“详情 -> 加入购物车 -> 查看购物车 -> 确认订单 -> 发起支付 -> 刷新支付结果”推进。购物车、金额、订单号和状态均来自服务端；页面刷新或返回后可用订单 ID 重新查询。
- 支付等待、失败和成功使用独立状态表达。`startPayment` 返回 `PENDING` 时只能显示等待 Provider 回调；刷新订单得到 `FAILED` 后保留订单和重试入口，得到 `SUCCEEDED` 后显示已支付且禁止重复发起。
- Playwright 使用真实 Oracle 数据和真实 HMAC Provider 回调验证成功/失败，不拦截 API；截图写入 `block_trading_client/screenshots/r1-production`。
