# 业务模块文档：推荐与内容分发

## 模块目标

聚合社区与商城内容，并通过订单状态汇总重要通知，提供可解释、可反馈并可恢复浏览位置的移动端信息流。首页的业务目标是把用户引导到参团、购买或处理业务状态，而不是单纯提高内容浏览时长。

## 本期实施范围

- 建立顶部附近区域、扫一扫和独立搜索入口，以及支持手动滚动和按组三条自动循环的订单状态轮播；当前定位统一优先显示市区，缺失市区时才显示街道，首页右上角不展示通知按钮。
- 支持关注、拼单、拼车、线下组队、线上开黑、近邻互助、商城七类筛选，业务筛选统一使用右侧抽屉。
- 支持社区与商城卡片混排并显示推荐原因，内容列表不插入活动提醒或其他通知卡片。
- 支持刷新、分页、卡片负反馈、分享、举报和撤销。
- 支持市区手动切换和定位拒绝后的可用状态；定位返回缺失市区时支持街道兜底展示。
- 支持今日首推、推荐社区卡片和商城商品卡片进入各自详情；“去参与”等参与按钮仅显示消息提示。
- 今日首推固定排在订单状态之后、分类入口之前；用户下滚后收起为可点击恢复入口，恢复不改变筛选、分页或滚动位置。
- 今日首推外层不显示边框，右侧信息列保留上、右、下三边描边，并为标题、推荐原因、时间和主操作保留足够纵向间隔。
- 记录曝光、点击、参与、购买、通知处理和负反馈事件。

## 页面业务流程

```text
进入推荐页
  -> 恢复筛选、列表页数与滚动位置
  -> 获取附近区域、未读摘要和首批混排内容
  -> 用户筛选 / 刷新 / 浏览
  -> 进入社区详情、商品详情，或从订单状态进入消息中心
  -> 在详情页查看信息，或由主操作显示消息提示
  -> 返回推荐页并恢复原位置
```

## 分发规则

1. 已参与或已关注业务的高优先级变化最先展示。
2. 关注列表按拼单、拼车、线下组队、线上开黑优先级分发。
3. 商城内容根据近期浏览和分类偏好插入，每六条最多两条。
4. 高优先级通知不插入内容列表；首页不提供通知按钮，统一由订单状态和底部消息入口承载。
5. 连续三条内容不得全部来自同一业务类型。
6. 已负反馈内容立即从当前会话移除，后续分页不得重新出现。
7. 已取消且与用户无关系、已下架商品和风险内容不得进入推荐池。

## 搜索页规则

- 搜索按钮跳转独立搜索页，不在推荐页内展开输入框。
- 搜索页默认展示最近搜索和热门搜索，提交后按全部、社区、商城切换结果。
- 搜索结果必须携带内容类型、标题、关键状态、价格或人数，支持直接进入对应业务。
- 搜索页不展示底部一级导航，返回后回到推荐首页。

## 扫一扫规则

- 点击扫一扫请求后置摄像头并打开二维码取景框；关闭、切换页面或组件卸载时停止全部视频轨道。
- 相机权限拒绝、设备不可用或浏览器不支持时保留扫描面板并显示明确降级提示。

## 分类列表规则

- 分类入口为关注、拼单、拼车、线下组队、线上开黑、商城。
- 列表头部显示分类标题、说明、匹配数量和排序方式。
- 关注分类的列表标题为“为您推荐”，排序优先级为拼单、拼车、线下组队、线上开黑。
- 线下组队列表展示活动地点、集合时间和费用；线上开黑列表展示平台、开局时间、当前人数和最少/最多人数；拼车卡片同样展示当前人数和最少/最多人数。
- 其他分类复用统一卡片骨架，根据分类替换关键字段，不使用“旅游”“游戏”或“凑伙”作为首页筛选文案。

## 首页设计约束

- 订单状态标题固定为 12px 粗体，“查看全部”固定为 9px 中等字重和 11px 箭头；卡片取消默认纵向内边距，390px 基准视口下高度约 126px。
- 状态视窗固定为 92px，每行 28px、行间距 4px，同时展示三条，不因内容切换改变高度。
- 自动滚动每 5 秒触发一次，每次用 1.4 秒整组三条向上滚动；轨道按 A/B/A 组织，滚至末尾同内容副本后无感复位。
- 手动滚动支持触摸、鼠标滚轮和键盘，并按三条分组吸附；用户手动输入的优先级高于自动滚动。
- 手动输入开始时立即取消自动动画并暂停至少 6.5 秒，暂停结束后的下一次 5 秒周期从当前分组恢复自动循环，禁止两种滚动同时争抢位置。
- 关注分类的列表标题与排序条件均固定为“为您推荐”，不得改回“关注动态”或“关系优先”。
- 内容列表只混排社区和商城卡片；活动提醒及其他通知只允许出现在订单状态和消息中心。

## 校园版过滤

- 推荐流和独立搜索页读取当前用户的 `campusMode` 与 `campusId`。
- `campusMode` 开启时，用户发布内容仅在 `authorId` 为当前用户、作者已关注或 `campusId` 匹配当前用户时返回；商城商品和系统通知不套用该过滤。
- 发布社区帖子时写入 `visibilityScope=campus` 作为校园版默认值，关闭校园版时写入 `visibilityScope=public`。

## 状态处理

| 业务状态 | 推荐页处理 |
|---|---|
| 社区招募中 | 显示人数进度和“去参与” |
| 用户已参与 | 显示“查看进度” |
| 社区已满员 | 保留卡片，说明已满员，主操作为查看详情 |
| 社区已截止 | 保留历史信息，说明截止时间 |
| 社区已取消 | 仅对已参与或已关注用户保留，并说明取消原因 |
| 商品可售 | 显示价格、库存和“去看看” |
| 商品售罄 | 保留“去看看”，在商品详情表达售罄 |
| 通知未处理 | 在订单状态或消息中心显示对应动作和业务深链 |
| 通知已处理 | 从订单状态移除，消息中心继续保留 |
| 网络离线 | 使用缓存内容并展示最后更新时间 |

## 负反馈规则

- “不感兴趣”针对单条内容，立即隐藏并支持 5 秒撤销。
- “减少此类内容”同时作用于内容类型或业务标签，但不完全屏蔽。
- “举报”进入独立治理流程，不作为普通推荐偏好处理。
- 已提交负反馈的内容不得在当前会话的刷新和分页中重新出现。
- 负反馈事件需记录内容标识、类型、原因、排序位置和当前筛选项。

## 位置恢复

- 进入详情前保存筛选项、已加载页码、内容顺序、隐藏内容和滚动偏移。
- 返回时优先恢复旧列表，不等待新请求完成后再定位。
- 缓存过期时以非阻断方式提示刷新，不直接把用户拉回顶部。
- 重复点击底部推荐入口时回到顶部并刷新，这一行为与普通返回区分。

## 交互验收

- 区域选择抽屉可以打开、选择区或街道并反映到首页。
- 搜索入口可以展开、输入并提交，提交结果有明确反馈。
- 六个分类均可切换；业务筛选从右侧抽屉打开，当前条件通过摘要和选中状态表达。
- 今日首推可以从“去参与”切换为“查看进度”。
- 社区与商品两种信息流卡片可被明确识别，内容列表不出现活动提醒卡片。
- 订单状态固定显示三行，每次整组三条慢速循环上滚，标题与操作文字层级清晰且纵向留白紧凑。
- 订单状态支持触摸、鼠标滚轮和键盘手动滚动，手动介入后自动滚动立即停止，并在至少 6.5 秒后的下一次周期恢复。
- 卡片更多菜单可以执行不感兴趣、减少此类、分享和举报。
- 不感兴趣后卡片隐藏，撤销后回到原位置附近。
- 商品详情跳转、刷新推荐和触底加载均有结果反馈；商品卡片不直接加购，同一页不得重复并发加载。
- 无更多、内容失效和定位拒绝具备可理解的文案与下一步。
- 开启校园版后，推荐和搜索结果符合本人/关注用户/同校区规则，且商品与系统通知仍可见。

## 非功能验收

- 移动端基准视口 390×844px 下无横向滚动和内容遮挡。
- 点击区域不小于 44×44px，图标按钮具有可访问名称。
- 动态未读数、人数和反馈文案不会导致主要布局明显跳动。
- 图片失败时仍可通过文字判断卡片类型和主要业务信息。
- 页面构建、类型检查和 lint 通过。

## 埋点验收

- 记录推荐页、筛选项、卡片与分页曝光。
- 记录详情点击、参与、加购、通知处理和返回继续浏览。
- 记录刷新结果、搜索提交、城市切换和定位授权结果。
- 记录不感兴趣、减少同类、撤销、分享和举报。
- 事件至少包含内容标识、内容类型、推荐位置、筛选项和推荐原因。
