# 业务模块文档：身份可见性与治理

## 模块目标

为 R1 五入口、移动管理端、PC 管理端和供应商回调提供统一身份、会话、学生认证、校园模式、双向拉黑、RBAC/区域范围、MFA、审核、举报、媒体授权和只读运维裁决。任何缓存、索引、消息或管理入口都不能绕过权威裁决。

## R1 状态与失败语义

- 会话状态只允许 `ANONYMOUS`、`ACTIVE`、`REVOKED`、`EXPIRED`；初始为 `ANONYMOUS`，`REVOKED` 与 `EXPIRED` 为终态。
- 学生认证只允许 `UNVERIFIED`、`PENDING`、`VERIFIED`、`REJECTED`、`REVOKED`；同一用户只允许一个 `PENDING` 或 `VERIFIED` 当前记录，只有 `VERIFIED` 可开启校园模式，撤销后立即关闭并发布失效事件。证明资产必须是本人上传且处于 `ACTIVE` 的 `STUDENT_PROOF`，学号只保存掩码和 SHA-256 摘要。
- 管理角色只允许 `SYSTEM_ADMIN`、`OPERATION_ADMIN`、`REGION_ADMIN`；普通用户没有管理角色。管理裁决同时校验资源、动作、范围、有效期、授权版本和 MFA。MFA 使用服务端 OTP 挑战状态机：随机码只经独立交付通道发送，Oracle 仅保存加盐 HMAC 摘要；5 分钟失效、最多 5 次失败、验证成功后只允许被同一用户和场景消费一次。DEV 可显式开启响应内测试码，默认与生产配置均关闭。
- 错误统一为 `ApiError{code,message,requestId,retryable,details}`。存在性可能泄露时使用 `NOT_FOUND_OR_HIDDEN`；策略、投影或依赖状态不确定时失败关闭。
- R1 API 使用无状态 Bearer 会话且不使用 Cookie 认证，安全链禁用 CSRF；浏览器来源仍按 `QH_ALLOWED_ORIGINS` 精确白名单校验，禁止 `*`。DEV 默认仅允许 `localhost:4200`、`127.0.0.1:4200` 和本地 Vite 端口，生产必须显式覆盖为实际 HTTPS 来源。

## 功能接口

接口版本为 `v1`，归属 `FR-IDENTITY-001`、`FR-VISIBILITY-001`、`FR-ACCESS-001`、`FR-ADMIN-001`、`FR-GOV-001`、`FR-MEDIA-001`、`FR-PLATFORM-001`。写接口除登录外均要求短期访问令牌，关键管理操作还要求 `X-MFA-Challenge` 和 `Idempotency-Key`。OpenAPI 基线位于 `../接口Schema/r1-openapi.yaml`，异步事件 Schema 位于 `../接口Schema/r1-events.schema.json`。

## 生产管理端与交互记录

- PC 管理端生产入口为 `block_trading_client/admin.html`，源码位于 `block_trading_client/src/App.tsx`；不复用原型 `#pc-admin`、角色切换器、静态队列或前端授权结论。
- 审核工作区从 `/capabilities` 和 `/moderation/cases` 读取权威事实。没有管理会话显示独立登录页；没有 `moderation.case.decide` 权限时只读展示，不渲染可提交的处置命令。
- 处置必须先选案件、结论和原因，再由服务端签发 `MODERATION_DECIDE` MFA 挑战。OTP 经独立通道交付；只有 DEV 显式开关返回 `devOtp`，生产界面不得生成、猜测或持久化 OTP。
- MFA 校验进入 `PASSED` 后，裁决请求携带 `X-MFA-Challenge` 和 `Idempotency-Key`；Oracle 在同一事务消费挑战、写裁决、更新案件、写审计和 Outbox。成功后刷新队列，失败保留已选原因并显示服务端错误。
