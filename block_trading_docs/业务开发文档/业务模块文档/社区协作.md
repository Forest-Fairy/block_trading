# 业务模块文档：社区协作

## 模块目标

提供购物拼单、出行拼车、线下组队、线上开黑和近邻互助的发布、发现、参与、管理与结果闭环。

## 首期任务

- 建立五类帖子的公共字段和差异字段。
- 草稿由独立草稿实体维护；提交校验通过后创建正式帖子，并实现审核、审核被拒、招募、达标、进行、完成、满员、取消和超时状态。审核被拒后修改内容回填到新草稿，不让正式帖子退回草稿状态。
- 实现参与、退出、申请审核、分享和人数进度。
- 为线下活动补充隐私、举报、拉黑和安全提示。
- 建立发现与我参与的双视图，支持分类、筛选、排序和状态恢复；列表内不设置搜索框。
- 社区顶部只提供全局搜索，通知统一由底部消息入口承载；社区首页不展示添加按钮，发布能力由后续业务入口接入。
- 建立触底分页、加载防重、失败重试和暂无更多反馈。

## 页面业务流程

```text
进入社区
  -> 恢复视图、分类、筛选、页数与滚动位置
  -> 加载首批 4 条活动
  -> 分类 / 筛选 / 排序 / 浏览，或从顶部进入全局搜索
  -> 触底追加下一页，保持已曝光顺序和滚动位置
  -> 进入帖子详情并参与，或从业务入口打开发布 Sheet 保存草稿
  -> 返回社区并恢复原位置
```

## 发现列表规则

- 视图分为“发现”和“我参与的”；发现用于匹配可参与活动，我参与的用于处理个人业务进度。
- 分类固定为全部、拼单、拼车、线下组队、线上开黑、近邻互助，不并列维护第二套分类卡片入口。
- 全部分类支持 5km 内、今天、仅看已认证；拼单、拼车、线下组队、线上开黑分别通过右侧筛选抽屉提供业务排序和指定条件。
- 视图、分类、筛选或排序变化时取消旧分页，从第一页重新查询，并更新匹配数量；搜索统一进入独立搜索页。
- 社区卡片必须携带类型、标题、时间、地点或线上属性、当前人数与人数范围、截止和认证状态。

## 帖子详情规则

- 五类帖子均从推荐、搜索或社区卡片进入独立详情，返回时恢复来源列表状态。
- 帖子详情顶部固定展示不可点击的帖子类型浅底标签和标题；媒体使用固定尺寸、按原始比例完整显示的多图轮播。同一图片在底层按当前原型参数 `scale-100`、`brightness-90`、`saturate-100`、`blur-9xl` 与 `opacity-90` 呈现，并叠加 `black/15` 的轻暗色毛玻璃层填充两侧余白；当前景产生左右余白时，仅在实际图片左右边缘使用透明渐变蒙版，让暗色毛玻璃背景过渡到清晰主体，主体中央保持清晰，顶部不留白。默认每 5 秒自动切换，支持触摸/鼠标横向滑动、键盘左右键和当前索引。左右翻页按钮的指针事件不得进入轮播手势捕获层，以支持电脑端单击和快速连击。手动操作后暂停自动切换至少 6 秒，再从当前索引恢复；圆点指示器位于图片内部底部安全区，使用 `1px` 白色描边，活动项使用白色填充。
- 详情正文顺序固定为发起人说明或备注、参与进度、类型详细信息、风险/隐私提示、操作区和留言列表。
- 新增近邻互助类型，用于附近临时资源或协助需求。持久化字段包括 `title`、`images`、`description`、`reward`、`timeliness`（instant/window）、`neededAt` 或 `neededStartAt/neededEndAt`、`latestResponseAt`、`urgent` 和公开范围。
- 留言领域模型支持 `commentId` 与可选 `parentReplyId`；回复及回复的回复必须在所属留言卡片内按缩进层级呈现，并聚合留言数与评论总数。留言和回复 DTO 均返回 `canReport`；更多菜单的举报请求携带对象类型、对象 ID、原因和补充说明，受理成功后不重复提交。
- 游客查询仅返回 5 km 内公开的近邻互助；详情 DTO 仅返回单一 `coverImage`、距离、类型、截断至 30 字的描述、留言数和评论总数，不返回作者、完整媒体、精确报酬、进度或互动内容。
- 拼单详情维护商品、规格、人均价格、数量、收货地点和交付方式。
- 拼车详情维护路线、上车地点、出行时间、费用、最少同行人数和最多座位。
- 线下组队详情维护目的地、集合时间、人均消费、最少/最多人数和成员要求。
- 线上开黑详情维护游戏类目、平台、开始时间、时长、最少/最多人数和段位或语音要求。
- 详情主操作根据状态和参与关系切换为去参与、申请加入、查看进度或已结束。

## 校园版与发布可见性

- 学生认证记录学校和 `campusId`，认证状态仅当前用户可见；未认证用户不可开启校园版。
- 校园版开启时，发现和搜索查询对用户发布内容应用本人、关注作者或同校区三选一规则；商城商品不属于社区查询范围。
- 发布请求增加 `visibilityScope`，校园版开启默认使用 `campus`，关闭时使用 `public`，发布 Sheet 必须展示当前默认范围。
- 顶部状态栏右侧提供校园版预览按钮，开启后模拟当前为已认证学生用户；开启后社区页面标题和底部导航标签统一使用“校园”。

## 触底分页规则

1. 首批返回 4 条，列表末端哨兵进入视口后请求下一页。
2. 同一查询条件只允许一个进行中的分页请求，重复触底直接忽略。
3. 下一页追加到旧列表末尾，不重新排序旧数据，不改变滚动位置。
4. 查询条件变化或刷新时取消旧请求、重置页码和是否还有更多。
5. 请求失败保留旧列表并提供原地重试；最后一页停止观察并显示暂无更多。

## 发布与参与规则

- 发布先选择拼单、拼车、线下组队、线上开黑或近邻互助，再填写公共字段和类型差异字段。
- 草稿本地或服务端自动保存；提交审核前校验必填项、敏感词和外部交易引导。
- 购物拼单默认即时参与；出行、线下组队和高风险活动可配置申请加入。
- 参与成功后更新当前人数并进入我参与的，支付状态与参与状态分开维护；拼车和线上开黑达到最少人数即可成立，达到最多人数后停止招募。
- 手动退出、活动取消、费用、地点和时间变化需要产生业务通知；正式状态迁移写入帖子状态流水，取消、超时和审核拒绝原因不得只保存在展示文案或 JSON 快照中。

## 页面状态

| 状态 | 页面处理 |
|---|---|
| 首次加载 | 列表骨架，不隐藏顶部筛选 |
| 触底加载 | 列表末端轻量加载提示，旧内容保持可操作 |
| 加载失败 | 末端显示原因和重试，不清空旧内容 |
| 暂无更多 | 停止触底观察，显示“暂无更多内容” |
| 筛选无结果 | 保留筛选，提供清除筛选和发起活动 |
| 草稿已保存 | 页面内提示可在我的继续编辑 |
| 活动失效 | 保留原因，禁用参与并允许查看详情 |

## R1 生产交互记录

- 生产源码：`block_trading_client/src/App.tsx` 的 `CommunityView` 与 `CommunityDetail`，移动 Web 和小程序入口共享交互语义，但只调用 `/api/client/v1` 版本化接口，不复制原型静态数据或角色切换。
- 帖子卡片进入独立详情状态；返回时保留社区列表数据和滚动容器。分享落地使用 `?share=<shareCode>`，每次进入都调用分享解析接口重新执行服务端可见性裁决，失败时保留可重试错误页。
- 详情按帖子、评论两个远程状态分别显示加载、空和失败；登录用户可创建顶层评论、对顶层评论做一级回复、创建分享码和举报，游客看到明确的登录门禁且前端不产生成功假象。
- 评论提交成功后重新读取服务端列表；二级回复不提供入口。举报提交成功后锁定当前详情的重复提交按钮，服务端仍以用户、目标和幂等键保证单一事实。
- 生产验收截图写入 `block_trading_client/screenshots/r1-production/`，至少包含移动详情与评论、游客拒写、小程序分享落地和举报受理状态；Playwright 同时断言无控制台错误、无横向溢出且底部操作不被导航遮挡。

## 数据模型与实体设计

- 五类帖子统一使用独立草稿、帖子主实体、地点、媒体、参与记录、字段变更日志、状态流水和类型扩展实体；字段矩阵、必填规则、隐私边界、索引与 Oracle 逻辑实体设计见 [帖子领域建模](帖子领域建模.md)。
- 发布、参与和详情 DTO 不得重新拼接展示字符串作为业务数据源；金额、人数、时间、地点和可见范围必须读取结构化字段。

## 服务端生产分层切片

- UserInterface 由 `R1ClientController` 提供版本化帖子、评论、分享和举报 HTTP 接口；Application 由 `DefaultCommunityUseCases`、`DefaultCommunityInteractionUseCases` 负责编排登录门禁、校验和页大小；Domain 端口为 `CommunityRepository` 与 `CommunityInteractionRepository`。
- Oracle Adapter 使用 Jimmer 查询与 MyBatis-Flex 命令，在单一 Spring 本地事务内完成评论/回复、参与、举报、审核案件与 Outbox；评论只允许一层回复，分享解析和评论读取均在返回前复核帖子可见性。
- V006 为评论、分享和举报补齐请求、幂等、证据、区域和版本字段；真实 Oracle、RabbitMQ Outbox/Inbox 与 MinIO 举报证据均已有运行证据，不使用内存 Repository 或 ORM 自动 DDL。
- 验证入口：仓库根目录执行 `gradlew check`，生产浏览器验收在 `block_trading_client` 执行 `npm run test:e2e`。

## 验收重点

- 人数状态、支付状态和活动状态相互独立。
- 拼车和线上开黑能分别校验最少人数与最多人数；达到最多人数、截止和取消时主操作正确禁用。
- 费用、地点和时间变更会产生业务通知。
- 发现/我参与的、分类、筛选和排序可组合使用并正确重置分页；列表无搜索框，全局搜索入口正常。
- 触底加载只触发一次并在尾部追加，加载、失败和暂无更多状态不遮挡旧内容。
- 卡片可直接判断类型、时间、地点、人数、截止与认证，敏感联系方式不公开。
- 社区首页无添加按钮；发布 Sheet 的字段模型仍保留，待后续业务入口接入。
- 五类帖子均可进入详情，详情字段和主操作随类型、人数上下限、互助时效及状态变化。
- 学生认证、校园版开关和帖子默认可见范围可操作；列表过滤和关注用户例外规则与需求一致。
- 390×844px 与桌面预览无横向溢出或底部遮挡，lint、构建和截图复核通过。

## 功能接口

接口版本为 `v1`，归属 `FR-COMMUNITY-001`、`FR-COMMUNITY-002`、`FR-COMMUNITY-003`、`FR-ASSIST-001`。所有写接口要求登录和 `Idempotency-Key`；帖子类型只允许 `GROUP_BUY`、`CARPOOL`、`OFFLINE_TEAM`、`ONLINE_TEAM`、`NEIGHBOR_HELP`。正式帖子初始状态为 `PENDING_REVIEW`，不可见对象统一返回 `NOT_FOUND_OR_HIDDEN`；乐观锁冲突返回 `CONFLICT`。适用用例为 `R1_COMMUNITY_001` 至 `R1_COMMUNITY_006`、`R1_MOD_001`、`R1_MOD_002`、`R1_ASSIST_001`。
