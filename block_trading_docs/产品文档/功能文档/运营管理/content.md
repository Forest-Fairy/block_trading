# 运营管理

## 功能定位

运营管理同时提供响应式移动管理界面与独立 PC Web 后台。三类管理员均可从已登录客户端设置进入对应的移动管理界面，也可从独立 PC 后台入口登录；移动端面向待办、轻量审核、区域工单和应急处置，PC 端面向批量处理、配置、审计、导出与高风险操作。所有管理能力均不得以共享账号、表格、客户端隐藏入口或请求参数替代服务端权限控制。

## 角色与数据范围

| 角色 | 管辖范围 | R1 核心职责 | 禁止或需审批的操作 |
|---|---|---|---|
| 系统管理员 | 全局 | 在移动管理界面查看系统待办和执行应急操作，在 PC 后台管理角色与权限、区域开关、规则版本、审计与受控运维 | 不直接批量代替审核人员处置普通内容；涉及资金、数据导出、全局规则发布和跨区域影响的操作必须二次验证并留痕 |
| 运营管理员 | 全局业务范围，但受岗位授权约束 | 在移动管理界面处理轻量审核和客服升级，在 PC 后台批量处理队列、运营素材、公告与经营汇总 | 不得修改角色权限、区域归属、系统密钥或审核规则；访问精确位置、联系方式、订单明细和导出数据须按业务必要性审批 |
| 区域管理员 | 被授权的城市、校区或服务区域 | 在移动管理界面或 PC 后台处理本区域审核、活动下架、公告、客服工单和区域运营素材 | 不得查看或操作其他区域的内容、用户明细、订单和工单；不得发布全局公告、修改全局规则、变更权限或执行资金操作 |

所有已登录主体共用 `qh_user` 账户表。`qh_admin_role_grant` 直接关联 `user_id`，以角色、权限、资源动作、范围、有效期和状态决定管理能力；游客不创建用户记录，也不能持有管理授权。角色、区域和数据范围必须由服务端逐请求校验。后台页面、客户端区域管理入口、接口、导出任务和异步审核队列均须带入当前操作人的角色与区域范围；前端隐藏菜单、请求参数中的区域 ID 或共享账号均不能作为数据隔离手段。

## R1 后台能力

### 审核与举报处置

1. 帖子提交及帖子、留言、回复的举报进入统一队列，并展示对象、所在区域、规则命中摘要、大模型建议、当前状态、时限和历史处理记录。
2. 审核链严格按“规则匹配 -> 大模型审核 -> 人工审核”流转。明确低风险的规则命中可自动放行或拦截；任何需要公开、下架、驳回或进一步风险处置的最终结论均由人工审核确认。
3. 高危命中可自动临时下架并进入人工加急队列。人工审核可作出通过、要求修改、驳回、维持下架、恢复展示或转交系统管理员的结论，并必须填写原因分类。
4. 区域管理员仅可处理授权区域队列；运营管理员可处理全局队列；系统管理员负责规则、模型和队列异常的配置与升级，不以权限身份绕过普通人工审核流程。

### 区域运营与应急

- 系统管理员维护城市、校区、配送范围、区域启停、可用业务、生效时间和应急下线开关。
- 运营管理员维护全局公告、运营素材和模板；区域管理员维护本区域公告、活动和服务信息，发布范围不得超出授权区域。
- 对区域暂停、内容批量下架、公告发布、规则发布和权限变更记录操作原因、影响范围、操作人、审批人、时间和结果；区域停用应保留用户订单、售后、客服和申诉入口。
- 系统管理员维护安全事件分级、值班升级、证据保全和用户通知模板；区域管理员可发起本区域人身安全、诈骗、账号盗用和隐私泄露事件，运营管理员负责跨区域协调。紧急事件可临时关闭高风险功能或区域，但必须记录恢复条件和复盘结果。

### 用户保护与合规

- 后台可配置年龄门槛、未成年人默认隐私与陌生人互动限制、规则和协议版本生效时间；系统管理员发布全局规则，区域管理员只能配置本区域补充规则，且不得降低全局保护要求。
- 后台展示注册、登录、发帖、举报、私信、邀请和审核提交的频率/验证码/设备风险命中情况。运营管理员和区域管理员只能处理风险队列与误伤申诉，系统管理员才可调整全局阈值或风控开关。
- 数据导出、删除请求、泄露事件、备份恢复和灾备演练均生成工单与审计记录；R3 前后台至少可检索请求、责任人、状态和处理结果。
- 系统管理员配置校园/地区/对象可见范围、拉黑关系的双向隔离策略和索引/缓存/异步任务失效策略；运营管理员与区域管理员可查看脱敏后的权限拦截量和失效任务状态，但不能以运营需要越过用户关系或可见范围。任何规则调整必须记录生效范围、版本、操作人、审批人及回滚条件。

### 部署与日志运维

- 系统管理员可查看部署号、环境、部署单元、制品版本、数据库数据源引用、目标 schema、迁移基线、执行阶段、操作者/流水线、开始结束时间和失败原因；后台只展示受控引用与脱敏信息，不返回 JDBC 密钥。
- 系统管理员可按时间范围、日志级别、服务、环境、deployment_no、节点/Pod、关键字、request_id、trace_id 和 error_code 组合筛选日志，并从 request_id/trace_id 进入跨服务时间线；默认按时间倒序分页，查询范围和返回条数受服务端限制。
- 日志写入前完成令牌、密码、证件、电话、精确地址和请求体敏感字段脱敏。普通运营管理员与区域管理员不得查看基础设施原始日志；确需排障时由系统管理员按最小范围授权，并记录查询条件、目的与查看结果审计。
- 后台展示在线切片与月度归档的覆盖月份、服务、文件数、总大小、SHA-256 校验结果、保留期限和最近作业结果；可重试失败归档，但不得在归档校验成功前删除源切片，也不得绕过法律保留或证据保全。
- 具体参数、状态、脚本和接口从[部署与运维管理导航](../../模块文档/部署与运维管理/navigator.csv)进入模块正文查看。

### 工单、审计与交接

- 举报、客服、售后、物流异常和安全事件使用可分配、可升级、可转交、可关闭的工单状态，并记录处理时限与用户通知。
- 每次审核、下架、恢复、区域切换、权限变更、导出和数据查看都记录操作者、角色、区域、对象、前后状态、理由和时间；审计记录不可由普通运营角色删除或改写。
- 管理员必须使用本人 `qh_user` 身份、最小权限和敏感操作二次验证，禁止共享账号；移动端与 PC 端使用同一角色授权。人员岗位或区域职责变更时，先回收旧权限再授予新范围。
- R2 增加履约评价申诉、反刷、争议证据、物流异常和调解工单；后台按承运商、区域、商品类型和履约批次查看发货、揽收、运输、派送、签收与异常节点，并可执行核验、催件、补发、退款或售后转交。关键安全、退款、取消与物流异常通知可查看送达、重试、已读确认和备用触达状态。R4 增加封禁申诉、关联反欺诈、算法处置和侵权投诉工单，但自动策略均须可人工复核和关闭。

## 后台原型初步完善范围

独立 PC 后台与移动管理界面复用同一角色、迭代和能力清单，但呈现密度不同。PC 端提供总览、审核队列、工单、审计和权限五个工作区；移动端保留相同业务语义，以卡片、分段页签和单项处置为主，不提供批量配置。原型静态数据只用于验证信息结构和交互，不代表已接入生产接口。

| 工作区 | 初版内容 | 角色差异与交互 |
|---|---|---|
| 总览 | 待审核、加急、SLA 风险、今日已处理指标；当前迭代队列；系统健康与受控运维摘要 | 运营管理员看到业务队列，系统管理员额外看到策略同步、部署与应急状态 |
| 审核队列 | 类型、区域、风险、时限、规则/模型摘要、当前状态与详情 | 支持关键字和风险筛选；打开详情后可模拟通过、要求修改、维持下架或升级，处置必须选择原因 |
| 工单 | 举报、客服、安全、交易或履约工单的负责人、优先级、状态与 SLA | 支持接单、升级和完成的原型状态；区域管理员只出现授权区域工单 |
| 审计 | 操作者、角色、动作、对象、范围、结果与时间 | 支持关键字检索；导出只生成待审批请求，不直接下载敏感数据 |
| 权限 | 当前主体、角色、数据范围、有效期和 Casbin 投影版本 | 运营管理员只读自身授权；系统管理员可发起授权变更，但必须经过二次验证/审批提示 |

区域管理员使用独立的区域工作台，包含区域选择、授权范围、内容/举报队列、公告和服务工单。区域切换只能在 `regionScope` 返回的授权集合内进行；跨区域、全局公告、权限变更、资金与系统配置不得出现可执行入口。

### 原型交互验收

1. 系统管理员与运营管理员进入同一后台框架，但导航内容、操作按钮和权限说明符合角色边界。
2. 审核队列可筛选、打开详情并完成一次带原因的模拟处置；处置后列表状态和汇总数同步变化。
3. 工单可完成接单或升级的模拟流转，审计工作区可检索并生成待审批导出请求。
4. 系统管理员可发起授权变更确认，运营管理员只能查看自身角色和范围。
5. 区域管理员只能切换已授权区域，区域队列、公告和工单均明确当前范围。
6. PC 宽屏和移动管理界面无横向溢出、无嵌套交互元素，浏览器控制台无错误。

## 发布验收

1. R1 前，系统管理员、运营管理员和区域管理员均可使用本人 `qh_user` 从客户端设置进入移动管理界面，并可从独立 PC Web 入口登录后台；两端均不可通过修改请求参数访问超出授权范围的数据。
2. 帖子提交和举报内容能依次产生规则匹配、大模型审核、人工审核记录；人工最终结论能同步给用户端审核状态和申诉入口。
3. 区域管理员只能处理本区域队列和发布本区域公告；运营管理员不能修改权限与系统规则；系统管理员能紧急停用指定区域或功能。
4. 高危内容可临时下架并进入人工加急队列；区域停用不会阻断已有订单、售后、客服和申诉。
5. 审核、工单、区域开关、公告、权限变更和数据导出均生成可检索审计记录，高风险操作具备二次验证或审批记录。
6. R1 能配置未成年人默认保护、查看反自动化风险队列并发起安全事件升级；R2 能处理评价、证据、物流异常和通知送达异常，且不因签收回传自动关闭争议；R3 能追踪数据请求和灾备演练；R4 自动风控、算法和侵权处置均保留人工复核与关闭开关。
7. R1 校园版、拉黑关系、搜索、推荐、详情、分享落地页和缓存恢复均通过服务端可见性校验；任何一方拉黑后，双方无法访问对方的资料、用户发布内容和互动，且相关索引、推荐候选、缓存和异步分发任务可追踪地失效。
8. R1 系统管理员可查看部署执行记录，并按 deployment_no、服务、时间、级别、关键字、request_id 或 trace_id 查询脱敏日志；运营管理员和区域管理员不能直接读取基础设施原始日志。
9. 日期/大小切片、月度归档、校验、保留与清理结果可见；失败归档可以重试，校验失败或存在法律保留时源日志不会被删除。
