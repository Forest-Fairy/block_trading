# 移动端产品设计

## 设计目标

移动端承担趣汇完整用户体验。五个一级页面分别解决“发现、参与、购买、沟通、管理”五类任务，同时通过推荐流、消息状态和个人业务概览形成跨页面闭环。

## 导航结构

底部导航栏固定显示五个入口：推荐、社区、商城、消息、我的。导航栏高度包含设备安全区；图标和文字同时表达当前页面，消息入口在有未读内容时显示数量徽标。

| 页面 | 图标语义 | 默认行为 | 二次点击 |
|---|---|---|---|
| 推荐 | 首页/发现 | 恢复上次浏览位置 | 回到顶部并刷新 |
| 社区 | 多人/协作 | 保留分类和筛选条件 | 回到社区首页 |
| 商城 | 购物袋 | 保留分类和列表位置 | 回到商城首页 |
| 消息 | 对话/通知 | 定位最近消息 | 回到消息顶部 |
| 我的 | 用户 | 展示最新账户状态 | 刷新个人数据 |

## 页面关系

```text
推荐 ──社区内容──> 社区详情 ──参与/发起──> 业务通知
  │
  ├──商城内容──> 商品详情 ──购买──> 商城订单
  │
  └──通知摘要──> 系统/业务通知详情

消息 ──用户会话──> 私聊或群聊

社区 ──活动状态变化──> 消息
商城 ──订单状态变化──> 消息
我的 ──业务概览──> 社区记录/商城订单/收藏
```

## 原型页面与组件边界

- `App.tsx` 只负责当前页面、未读数、学生认证、校园版、原型会话与迭代状态等跨页状态，以及手机外壳和页面切换组合。
- 推荐、独立搜索、社区、商城、消息、我的分别使用独立页面模块；页面模块只组合本页面状态、交互和数据加载。
- 状态栏、底部导航、页面标题、社区卡片和商品卡片作为共享原型组件复用；活动、商品、小程序等静态演示数据与可见性规则集中维护。
- 原型继续使用现有 `PageKey` 状态模拟路由，不为静态原型新增路由框架；独立搜索、帖子详情和 `CommerceFlowPage.tsx` 交易流程视为沉浸式子流程，进入时隐藏底部导航，返回时恢复来源页。
- 商品详情与帖子详情均使用左上角返回按钮；一级页面的搜索、通知和购物车等工具操作继续放在右侧。
- 消息的系统通知、业务通知、私聊和群聊属于 `MessagesPage.tsx` 内部二级状态；不在 `App.tsx` 堆叠消息业务布局。
- 帖子详情使用独立 `src/pages/PostDetailPage.tsx`，通过活动类型数据驱动拼单、拼车、线下组队和线上开黑的差异字段。
- 帖子详情顶部使用不可点击的浅底类型标签紧邻标题；图片区域使用多图轮播，正文按发起人备注/进度、详细信息、提示和留言列表分层。
- 区域管理工作台使用独立 `RegionManagementPage.tsx`；运营和系统工作台使用独立 `AdminConsolePage.tsx`。三类管理员均可从客户端设置进入移动管理界面，也可从 `#pc-admin` 进入独立 PC 管理端；共享访问主体、RBAC 范围与迭代状态放在 `src/prototype/access.ts`。
- 新增页面或独立流程时必须先在本节明确页面级边界，再新增对应页面文件，禁止继续堆入 `App.tsx`。
- 系统悬浮助手由 `FloatingAssistant` 负责贴边、拖拽、收起和镜像菜单；`AssistantChatPage.tsx` 负责客服与智能建帖对话，手动表单作为该页面内部状态，二者共享同一份建帖草稿。

## 当前原型对齐基线

- 首页分类固定为关注、拼单、拼车、线下组队、线上开黑和商城；不再使用“旅游”“游戏”“凑伙”或“附近分类”作为入口文案。
- 关注列表默认按拼单、拼车、线下组队、线上开黑优先分发；各业务筛选条件从右侧抽屉进入。
- 社区列表不设置独立搜索框，顶部只保留全局搜索和通知；校园版开启后社区标题和底部导航标签显示“校园”。
- 推荐首页右上角只保留扫一扫和搜索，通知入口统一通过底部消息导航进入；社区页仍保留通知入口。
- 顶部状态栏右侧校园版按钮仅用于原型预览，开启后模拟当前用户已认证并应用校园可见性规则。
- 我的页面顺序为个人信息、更多趣汇小程序、兑换码、偏好设置、学生认证与校园版、退出登录；个人资料不展示用户编号。
- 小程序列表一次查询后记录查询时间，按当前性别适用、收藏、排序值（空值靠后）、使用频次和流量热度排序，60 秒内复用结果。
- 商城筛选抽屉移除“全部商品”，商品分类与商品状态均为可取消的多选复选框。
- 拼车和线上开黑同时维护当前人数、最少人数和最多人数，达到最少人数即可成立，达到最多人数后停止招募。

## 原型交付入口

- 原型预览入口：`block_trading_docs/产品原型/shadcn-mobile/`，本轮验收服务器访问 `http://127.0.0.1:5174/`（端口以实际启动参数为准），独立 PC 管理端为 `http://127.0.0.1:5174/#pc-admin`。
- 应用编排入口：`src/App.tsx`；共享数据：`src/prototype/data.ts`；共享外壳与卡片：`src/components/prototype-shell.tsx`。
- 页面模块：`src/pages/RecommendPage.tsx`、`SearchPage.tsx`、`CommunityPage.tsx`、`MallPage.tsx`、`ProductDetailPage.tsx`、`CommerceFlowPage.tsx`、`MessagesPage.tsx`、`PostDetailPage.tsx`、`ProfilePage.tsx`、`RegionManagementPage.tsx`、`AdminConsolePage.tsx`。
- 本轮截图复核：[游客 R1 交易预览](../../../产品原型/shadcn-mobile/screenshots/guest-commerce-r1-desktop.png)、[系统管理员独立 PC 后台](../../../产品原型/shadcn-mobile/screenshots/system-admin-r1-pc.png)；交互规则按本文件“原型页面与组件边界”执行。

## 权限与迭代原型

- 原型在宽屏手机外壳之外提供受控的“迭代”和“访问主体”切换；窄屏以固定的验收控制按钮打开底部抽屉并提供相同切换能力。两种控制区均不是用户端产品页面，也不代表生产环境允许用户自行切换角色。
- 游客可浏览推荐、社区、商城和消息中的公开预览；消息页默认仅展示一条未读入会系统通知。游客可查看商品、价格和交易流程说明，但收藏、购物车、下单、支付、发送消息、创建草稿、资料读取与管理操作均触发登录提示或拒绝状态。所有已登录用户均显示 `VIP_1` 至 `VIP_6` 权益状态。
- 三类管理员均从“我的 -> 设置”进入对应的响应式移动管理界面；同时提供独立 `#pc-admin` PC Web 后台入口。区域管理员只处理授权区域，运营管理员和系统管理员按岗位权限处理全局业务或系统能力。移动端与 PC 端共用服务端能力清单，生产请求仍校验角色、资源、动作、范围、有效期和高风险二次验证。
- 校园模式保留本人和有效关注关系例外：本人发布和已关注用户发布允许跨校区展示，其余用户发布内容仅展示当前校区；客户端不得通过伪造关注标记绕过服务端裁决。
- R1 表达游客/VIP/RBAC、双端管理入口与商城浏览、购物车、订单确认、基础支付和订单状态；R2 表达物流、退款、售后和区域交易收口；R3 表达多区域灰度与范围到期；R4 表达风险治理、审批与人工关闭开关。

## 跨页面规则

- 登录前允许浏览推荐、社区、商城和消息；游客消息仅保留入会引导系统通知，订单区域只显示能力预览，不展示真实订单。发布、参与、收藏、加购、下单、支付或发消息时触发登录；建帖助手可进入只读预览，但不提供输入控件且不保存草稿、帖子或会话。
- 从推荐进入详情后返回，应恢复原信息流位置和已曝光内容。
- 所有社区卡片必须显示业务类型、地点或线上属性、截止时间和人数进度。
- 所有商城卡片必须显示自营标识、价格和库存或售卖状态。
- 未读总数由系统通知、业务通知和用户消息共同计算，超过 99 显示 `99+`。
- 深链进入详情时仍保留完整底部导航，但支付、发布等沉浸式流程可临时隐藏。
- 系统悬浮助手在所有页面可用；聊天、手动填写和提交前确认属于沉浸式子流程，进入后隐藏底部导航和悬浮球，关闭或取消后恢复原页面。推荐页标题和预置位作为同一条粘性栏保留在内容区顶部，便于滚动后继续拖放。预置位弹出、接近、居中和嵌入各阶段均读取预置位元素当前 `DOMRect` 中心，再换算手机外壳坐标；布局半径使用未受动画缩放影响的尺寸。离开推荐页、切换身份或完成拖拽时必须清除残留指针状态，禁止后台页返回后继续跟随鼠标。

## 全局状态

| 状态 | 表达要求 |
|---|---|
| 加载中 | 优先使用骨架屏，避免内容区域跳动 |
| 空数据 | 说明当前无内容，并提供与场景相关的下一步操作 |
| 网络失败 | 保留已缓存内容，提供局部重试 |
| 权限不足 | 说明所需权限及用途，不直接反复请求系统授权 |
| 业务结束 | 保留历史信息，禁用主操作并解释结束原因 |
| 风险拦截 | 明确受限行为和申诉入口，不暴露风控规则细节 |

## 无障碍与可用性

- 正文不小于 14px，辅助信息不小于 12px。
- 点击区域不小于 44×44px。
- 颜色不作为唯一状态表达，必须配合图标或文本。
- 动态人数、倒计时和未读数变化不应引起布局跳动。
- 重要操作提供明确结果反馈，支付、退出和删除操作需要二次确认。
