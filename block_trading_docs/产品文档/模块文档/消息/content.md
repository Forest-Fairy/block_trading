# 消息

## 页面目标

消息页按重要性和业务属性组织信息，顶部固定系统通知，其后固定业务通知，再展示用户消息。用户无需进入多个业务页面即可了解平台状态、交易进度和沟通更新。

## 页面结构

1. 顶部栏：标题、全部已读和消息设置。
2. 系统通知：固定第一项，承载账号、安全、审核、规则和平台公告。
3. 业务通知：固定第二项，承载社区活动、商城订单、支付、退款和履约状态。
4. 用户消息：分组标题后展示会话列表，包括私信、活动成员沟通和客服。

## 通知优先级

| 级别 | 示例 | 表达方式 |
|---|---|---|
| 紧急 | 账号风险、支付异常、行程取消 | 顶部标识、强提醒、不可批量忽略 |
| 重要 | 成团、发货、退款结果、申请审核 | 未读徽标和业务状态色 |
| 普通 | 活动提醒、互动、运营公告 | 常规列表样式 |

## 列表规则

- 系统通知和业务通知展示最新一条摘要、时间及各自未读数。
- 用户会话按最新有效消息排序，置顶会话优先。
- 被撤回、屏蔽或风控拦截的内容使用明确占位说明。
- “全部已读”不影响要求用户确认的安全和协议类消息。

## 会话能力

- 支持文本、图片、商品卡片、社区活动卡片和系统提示。
- 支持举报、拉黑、删除会话和关闭提醒。
- 线下活动会话不得自动暴露手机号、地址等隐私信息。
- 订单和活动状态使用不可伪造的系统消息样式，与普通用户文本区分。

## 未读规则

底部消息徽标为三类未读总和；超过 99 显示 `99+`。进入分类不等于全部已读，只有内容进入可视区域或用户执行全部已读后才更新状态。

## 页面状态

| 状态 | 页面表现 |
|---|---|
| 无消息 | 保留系统和业务通知入口，用户消息区展示空状态 |
| 消息发送失败 | 原位置显示失败标识并支持重试 |
| 会话受限 | 说明禁言、拉黑或风险限制及申诉方式 |
| 离线 | 展示缓存消息，恢复网络后同步发送状态 |
