# 消息

## 页面目标

消息页按重要性和业务属性组织信息，顶部固定系统通知，其后固定业务通知，再展示用户消息。用户无需进入多个业务页面即可了解平台状态、交易进度和沟通更新。

## 页面结构

1. 顶部栏：标题、全部已读和消息设置。
2. 系统通知：固定第一项，承载账号、安全、审核、规则和平台公告。
3. 业务通知：固定第二项，承载社区活动、商城订单、支付、退款和履约状态。
4. 用户消息：分组标题后展示会话列表，包括私信、活动成员沟通和客服。

## 通知优先级

| 级别 | 示例 | 表达方式 |
|---|---|---|
| 紧急 | 账号风险、支付异常、行程取消 | 顶部标识、强提醒、不可批量忽略 |
| 重要 | 成团、发货、退款结果、申请审核 | 未读徽标和业务状态色 |
| 普通 | 活动提醒、互动、运营公告 | 常规列表样式 |

## 列表规则

- 系统通知和业务通知展示最新一条摘要、时间及各自未读数。
- 用户会话按最新有效消息排序，置顶会话优先。
- 被撤回、屏蔽或风控拦截的内容使用明确占位说明。
- “全部已读”不影响要求用户确认的安全和协议类消息。

## 会话能力

- 支持文本、图片、商品卡片、社区活动卡片和系统提示。
- 支持举报、拉黑、删除会话和关闭提醒。
- 线下活动会话不得自动暴露手机号、地址等隐私信息。
- 订单和活动状态使用不可伪造的系统消息样式，与普通用户文本区分。

## 二级页面与聊天界面

### 系统通知详情

- 从消息首页“系统通知”入口进入，顶部显示返回、标题“系统通知”和全部已读操作。
- 列表按时间倒序展示账号安全、平台公告、规则更新和审核结果；每条通知展示标题、时间、正文摘要、优先级和已读状态。
- 安全与协议类通知保留确认或查看规则动作，不因“全部已读”而跳过必要确认。

### 业务通知详情

- 从消息首页“业务通知”入口进入，顶部显示返回、标题“业务通知”和筛选/全部已读操作。
- 列表按业务时间倒序展示拼单成团、拼车确认、组队提醒，以及商品下单、支付、发货、签收、退款和售后状态。
- 业务通知必须带关联对象和状态标签；存在关联帖子或商品订单时提供“查看详情”动作，进入后可通过左上角返回按钮回到消息详情列表。

### 私聊与群聊

- 用户消息列表进入一对一私聊或活动群聊；顶部显示返回、对象名称、在线状态或群成员数以及更多操作。
- 会话正文区区分自己和对方的消息气泡，系统状态消息单独使用状态样式；群聊消息展示发送者昵称和头像。
- 底部输入区固定包含文本输入、发送按钮和附件入口；发送中、失败、重试、禁言/拉黑和离线缓存状态均需可见。
- 线下活动聊天不直接公开手机号、精确地址和其他敏感联系方式，必要信息通过业务卡片或确认成员后展示。

## 未读规则

底部消息徽标为三类未读总和；超过 99 显示 `99+`。进入分类不等于全部已读，只有内容进入可视区域或用户执行全部已读后才更新状态。

## 页面状态

| 状态 | 页面表现 |
|---|---|
| 无消息 | 保留系统和业务通知入口，用户消息区展示空状态 |
| 消息发送失败 | 原位置显示失败标识并支持重试 |
| 会话受限 | 说明禁言、拉黑或风险限制及申诉方式 |
| 离线 | 展示缓存消息，恢复网络后同步发送状态 |
| 通知详情为空 | 保留返回入口和分类说明，展示空状态 |
| 群聊受限 | 显示禁言、已解散或权限不足原因，并保留历史消息 |
