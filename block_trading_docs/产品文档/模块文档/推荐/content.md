# 推荐

## 页面定位

推荐页是趣汇移动端默认首页，承担跨业务发现与分发。页面将社区协作和商城商品组织成一条可解释、可反馈、可恢复位置的混合信息流；高优先级业务通知集中在订单状态和消息入口呈现，帮助用户在首屏完成“发现机会、判断是否相关、进入业务详情”三个动作。

推荐页不是活动宣传页，也不承担完整分类浏览职责。社区和商城仍是各自业务的深度浏览入口，推荐页只展示最值得用户立即处理或参与的内容。

## 目标用户任务

1. 快速确认当前附近区域、未读业务状态和可参与内容。
2. 按关注或业务类型收窄信息流。
3. 在卡片上判断内容类型、时间、地点、人数、价格和风险状态。
4. 直接进入社区详情、商品详情或对应业务通知。
5. 对不相关内容执行负反馈，让后续推荐更准确。
6. 从详情返回后继续原来的浏览位置，不重复阅读已曝光内容。

## 页面信息架构

页面从上到下固定为以下六层：

| 层级 | 内容 | 主要作用 | 首屏要求 |
|---|---|---|---|
| 1 | 品牌与工具栏 | 表达趣汇品牌、当前附近区域、扫一扫和搜索入口 | 始终可见 |
| 2 | 订单状态轮播 | 以三行紧凑轮播展示成团、发货、活动临近等状态 | 有状态时展示 |
| 3 | 今日首推 | 展示一条高相关、强时效内容 | 位于订单状态与兴趣分类之间，默认态展示 |
| 4 | 兴趣分类 | 关注、拼单、拼车、线下组队、线上开黑、商城 | 横向滚动，保留选中项 |
| 5 | 综合信息流 | 社区与商城两类卡片按规则混排 | 页面主体 |
| 6 | 分页与结果反馈 | 触底加载、局部重试、暂无更多 | 列表末尾展示 |

## 顶部栏

- 左侧显示“趣汇”主品牌和当前附近区域；当前定位优先只显示市区，市区缺失时才显示街道，可点击切换。
- 附近区域下方使用一句短提示表达当前推荐语境，不展示营销口号。
- 右侧提供扫一扫和搜索两个图标按钮，触控区域不小于 44×44px；首页右上角不再展示通知按钮。
- 点击扫一扫后请求后置摄像头并打开二维码取景框；关闭取景框时必须释放摄像头，权限拒绝或不可用时显示降级提示。
- 点击搜索按钮直接进入独立搜索页，首页不展开内联输入框。

## 独立搜索页

- 顶部为返回按钮、圆角搜索输入框和“取消”操作，输入框支持社区标题、地点、商品名称和订单状态。
- 未提交搜索词时展示最近搜索、热门搜索和搜索范围提示。
- 提交后按“全部、社区、商城”三类切换结果，结果卡片保留类型、标题、关键状态、价格或人数信息。
- 搜索为空时提示可尝试的示例关键词，不把用户留在无反馈页面。
- 从搜索页返回首页时回到推荐首页，不显示底部一级导航，避免与返回操作重复。

## 订单状态轮播

### 展示规则

- 仅展示与当前用户业务直接相关且需要及时处理的消息。
- 优先级顺序为：安全或取消通知、行程变更、成团与支付、活动即将开始、订单履约。
- 顶部使用清晰可辨的“订单状态”标题，“查看全部”使用更小的辅助操作字号，标题区不保留多余纵向留白。
- 内容区固定展示三行，行高和图标尺寸保持稳定；每 5 秒将当前三条作为一组，用 1.4 秒慢速上滚到下一组三条。
- 两组三条状态循环展示，整组切换完成后无感复位，不改变卡片高度，不出现内容瞬间跳换。
- 状态列表支持触摸拖动、鼠标滚轮和键盘上下滚动，手动滚动按三条分组吸附。
- 用户开始手动滚动时立即取消正在进行的自动动画，并暂停自动轮播至少 6.5 秒；暂停结束后的下一次 5 秒周期从当前分组继续自动循环。
- 点击任意一行进入消息中心或对应业务详情；首页未读数只通过底部消息导航承载。

### 关闭规则

- 用户可关闭当前摘要，关闭只影响本次首页会话，不改变消息未读状态。
- 同一条摘要关闭后，本次会话内不再次插入信息流。

## 首页推荐设计基线（冲突消解）

下表是本轮首页设计的统一规划基线。后续若局部说明、历史截图或实现样例与下表冲突，以本表为准，并同步修正对应说明，避免同一页面出现两套规则。

| 设计项 | 统一基线 | 冲突处理 |
|---|---|---|
| 订单状态标题 | 12px 粗体，使用正文前景色 | 不再使用 10px 弱化标题 |
| “查看全部” | 9px 中等字重，右侧 11px 箭头 | 始终低于订单状态标题层级 |
| 卡片留白 | 取消卡片默认纵向内边距；390px 基准视口下订单卡片约 126px 高 | 不通过增加上下空白制造层级 |
| 状态视窗 | 高 92px，每行 28px，行间距 4px，固定同时显示三条 | 内容变化不得撑高卡片 |
| 自动滚动 | 每 5 秒触发一次，每次整组三条，用 1.4 秒慢速向上滚动；A/B/A 轨道无感复位 | 不使用逐条跳换或瞬间替换 |
| 手动滚动 | 支持触摸、鼠标滚轮和键盘，按三条分组吸附 | 手动输入优先于自动滚动 |
| 自动恢复 | 手动输入立即取消当前自动动画并暂停至少 6.5 秒，在暂停结束后的下一次 5 秒周期从当前分组恢复 | 暂停期间自动滚动不得抢夺控制权 |
| 关注分类文案 | 列表标题和排序条件统一为“为您推荐” | 不再显示“关注动态”或“关系优先” |
| 内容列表边界 | 仅展示社区和商城卡片 | 活动提醒和其他通知只进入订单状态及消息中心 |

## 兴趣筛选

| 筛选项 | 内容范围 | 默认排序偏好 |
|---|---|---|
| 关注 | 已关注发起人、分类和已参与业务更新 | 为您推荐 |
| 拼单 | 购物拼单社区内容 | 价格、数量、收货地点距离或指定阈值/地点 |
| 拼车 | 出行拼车社区内容 | 上车地点、出行时间或指定上车地点/目的地/时间 |
| 线下组队 | 露营、徒步、羽毛球等线下活动 | 目的地距离、人均消费或指定消费/目的地/距离 |
| 线上开黑 | 在线游戏组队、桌游和电竞活动 | 开始时间、时长或指定阈值/游戏类目 |
| 商城 | 趣汇自营商品 | 偏好、上新、库存 |

- 默认选中“关注”；关注列表优先级为拼单、拼车、线下组队、线上开黑。
- 业务分类和商城的筛选条件统一从右侧筛选抽屉打开。
- 关注分类的列表标题和排序条件均显示“为您推荐”。
- 切换筛选项后保持页面顶部位置，并展示轻量结果反馈。
- 筛选项切换不清空用户已隐藏的内容。
- 当前筛选结果为空时提供切换其他分类或浏览全部社区的场景化入口。

### 校园版内容边界

- 用户在“我的 > 偏好设置”完成学生认证并开启校园版后，推荐流和搜索结果中的用户发布内容按当前校区过滤。
- 本人发布和关注用户发布的内容始终保留；商城商品、系统通知等非用户发布内容不参与同校区过滤。
- 新发社区帖子在校园版开启时默认写入“仅同校可见”，关闭校园版时默认公开可见。

### 分类列表设计

- 每个分类列表顶部展示分类标题、内容说明、匹配数量和当前排序方式。
- 关注：按四类业务优先级分发；拼单、拼车、线下组队和线上开黑的排序与指定条件通过右侧筛选抽屉表达；商城通过右侧抽屉提供分类、价格、排序、成色、库存和包邮条件。
- 列表卡片使用统一结构，但允许根据分类替换第二行关键字段，确保用户无需进入详情即可做初步判断。
- 分类切换保留滚动位置、已隐藏内容和加载页数；无结果时提供与当前分类相关的下一步入口。

## 今日首推

- 每次刷新最多展示一条今日首推，优先选择 24 小时内截止且与用户偏好高度相关的社区内容。
- 今日首推使用紧凑横向固定高度卡片：外层不显示边框或阴影，左侧封面图占卡片宽度 `38.2%`（`1 - 0.618`），贴合卡片左、上、下边缘；图片使用 `cover` 铺满容器并裁切，保证媒体区域完整覆盖。右侧信息列仅保留上、右、下三边描边和右侧圆角，第一行显示“今日首推”和距离，例如“距离你 2.8 km”，第二行显示帖子标题，下方展示推荐原因、时间、地点或线上属性、费用、发起人可信标识和当前进度，内容区使用较宽松的内边距与纵向间隔，主按钮固定在右侧内容的最底部。
- 主操作根据业务状态显示“去参与”“查看进度”或“查看详情”。
- 已满员、已截止或已取消时保留历史信息，并在主操作附近解释不可参与原因。
- 今日首推不使用自动轮播，避免用户阅读和操作过程中内容切换；订单状态轮播与其分离。
- 首屏将今日首推置于订单状态下方、兴趣分类上方；用户向下滚动浏览信息流后自动收起为“已收起今日首推”的轻量入口，点击入口恢复完整首推卡，不改变当前筛选和滚动位置。

## 综合信息流

### 混排原则

首期采用规则排序，不依赖不可解释的模型结果：

1. 用户已参与、已关注业务的状态变化优先。
2. 附近且即将截止、人数缺口较小的社区内容其次。
3. 匹配用户浏览或购买偏好的自营商品再次。
4. 高优先级通知不插入内容列表，统一通过订单状态轮播和消息入口承载。
5. 连续三条内容不得全部来自同一业务类型。
6. 每六条内容最多插入两条商城商品，避免首页被交易内容占满。
7. 已负反馈、已取消且与用户无关系的内容不再推荐。

### 推荐原因

每张业务卡片至少显示一个可理解的推荐原因，例如“距你 1.2 km”“你关注的露营”“还差 2 人成团”“最近浏览过通勤用品”。推荐原因不得暴露用户隐私、风控规则或其他用户的敏感行为。

## 内容卡片

### 社区卡片

- 类型仅允许购物拼单、出行拼车、线下组队、线上开黑。
- 显示封面、标题、类型、推荐原因、时间、地点或线上属性、人数进度和发起人信息。
- 拼单补充预估人均金额；拼车补充路线、当前人数、最少同行人数和最多座位；线下组队补充活动地点与费用；线上开黑补充平台、开局时间、当前人数、最少参与人数和最多人数。
- 主操作为“去参与”；用户已参与时显示“查看进度”。
- 已满员、已截止或已取消时显示结束原因，主操作降级为“查看详情”。
- 更多菜单包含“不感兴趣”“减少此类内容”“分享”“举报”。

### 商城卡片

- 明确显示“趣汇自营”，不得与用户发布的社区内容混淆。
- 显示产品图、名称、核心卖点、价格、库存状态和推荐原因。
- 点击卡片进入商品详情；商品卡片按钮统一为“去看看”，原型阶段不直接加购。
- 无库存时保留详情入口，按钮继续显示“去看看”，并在详情中表达售罄状态。
- 更多菜单包含“不感兴趣”“减少商城推荐”“分享”。

### 通知呈现边界

- 内容列表不展示活动提醒或其他通知卡片。
- 成团、支付、行程变更、活动即将开始和订单发货等状态统一进入顶部订单状态轮播及消息中心。

## 关键交互

### 刷新与分页

- 下拉刷新保持当前筛选项，刷新完成后在顶部提示“已更新 N 条内容”。
- 本期 Web 原型使用“刷新推荐”图标按钮模拟下拉刷新。
- 列表末端哨兵进入视口 120px 预加载范围时自动加载下一页，不展示“加载更多”按钮。
- 同一筛选同一时间只允许一个分页请求；重复触底忽略，切换筛选或刷新时重置分页和 pending 状态。
- 加载期间在列表尾部显示固定高度轻量状态，追加后保留已加载内容和滚动位置。
- 分页失败只替换列表尾部状态，保留已加载内容并提供“重新加载”。
- 没有更多内容时显示“今天先看到这里”，不循环展示相同卡片。

### 负反馈

1. 用户打开卡片更多菜单。
2. 选择“不感兴趣”后，卡片立即从当前信息流隐藏。
3. 页面底部显示可撤销反馈，撤销窗口为 5 秒。
4. 选择“减少此类内容”时同时记录内容类型偏好。
5. 举报进入原因选择和补充说明流程，不与普通负反馈混用。

### 附近区域与定位

- 点击附近区域打开底部抽屉，展示当前市区、常用市区和重新定位入口；定位结果缺失市区时才以街道兜底展示。
- 定位权限未授权时先说明用途，再由用户主动触发系统授权。
- 拒绝定位后允许手动选择市区，首页继续可用。
- 切换附近区域会刷新“附近”内容，但不修改关注关系。

### 返回恢复

- 从详情返回时恢复筛选项、已加载页数、已隐藏内容和滚动偏移。
- 页面数据超过缓存时效时先恢复位置，再以非阻断方式提示可刷新。
- 重复点击底部“推荐”入口时回到顶部，并触发一次显式刷新。

## 页面状态

| 状态 | 页面表现 | 可执行动作 |
|---|---|---|
| 首次使用 | 展示当前附近区域热门和关注内容，不强制兴趣问卷 | 浏览、切换筛选 |
| 未登录 | 正常浏览，默认筛选为关注 | 参与、购买时登录 |
| 刷新中 | 保留旧内容，顶部显示刷新进度 | 可继续浏览 |
| 分页中 | 列表末尾展示固定高度骨架 | 等待完成 |
| 无推荐 | 展示热门社区分类和商城新品入口 | 切换分类 |
| 分页失败 | 保留已加载内容，尾部显示错误说明 | 重新加载 |
| 离线 | 展示缓存内容并标记最后更新时间 | 重试联网 |
| 内容失效 | 卡片显示已满员、已截止或已取消及原因 | 查看历史详情 |
| 定位拒绝 | 保持当前附近区域或默认市区 | 手动选择市区 |
| 风险内容 | 从推荐流移除，不展示具体风控判断 | 在消息中查看处理结果 |

## 数据与埋点

### 核心字段

- 内容标识、内容类型、业务类型、推荐原因、排序位置、实验版本。
- 社区内容的时间、地点、人数、费用、状态和发起人可信标识。
- 商城内容的价格、库存、自营标识和推荐标签。
- 通知内容的优先级、关联业务、未读状态和动作类型。

### 关键事件

- 页面曝光、筛选切换、刷新、分页结果。
- 卡片曝光、点击、停留、参与、加购和通知处理。
- 不感兴趣、减少此类内容、撤销、分享和举报。
- 附近区域切换、定位授权结果、搜索提交和返回位置恢复。

### 成功指标

- 推荐卡片进入详情的点击率。
- 推荐到参团、购买或通知处理的转化率。
- 首屏有效内容点击率和 7 日返回率。
- 三类内容曝光占比、负反馈率和重复曝光率。
- 从详情返回后的继续浏览率。

- 点击订单状态任意一行或“查看全部”进入消息入口；状态列表支持手动滚动，并在无手动操作时每次按组三条慢速循环上滚。
- 点击兴趣分类切换内容范围，并显示分类标题、说明和匹配数量；分类为关注、拼单、拼车、线下组队、线上开黑、商城，各业务筛选从右侧抽屉打开。
- 点击今日首推主操作切换为已参与状态。
- 点击卡片更多按钮可执行不感兴趣、减少同类、分享或举报；不感兴趣支持撤销。
- 点击社区帖子卡片主体进入帖子详情；点击“去参与”等主操作只显示消息提示。
- 点击商品卡片主体进入商品详情；卡片按钮统一显示“去看看”，暂不直接加购。
- 点击刷新按钮模拟获取新一批内容；继续滚动到列表底部后自动追加下一批混排内容。
- 底部五入口保持可切换，用于验证推荐页与全局导航的一致性。

## 验收标准

1. 首屏能同时识别当前市区、扫一扫、搜索、订单状态轮播、筛选和一条今日首推；仅在市区缺失时显示街道，右上角不出现通知按钮。
2. 订单状态可通过触摸、鼠标滚轮和键盘手动滚动；手动输入时自动动画停止，至少 6.5 秒后的下一次自动周期才恢复。
3. 分类完整包含关注、拼单、拼车、线下组队、线上开黑和商城，不出现附近分类。
4. 信息流仅混排社区与商城卡片，不出现活动提醒或其他通知卡片，且类型标识不会混淆。
5. 社区卡片主体可进入帖子详情，主操作只显示消息提示；商城卡片可判断自营、价格和库存并进入商品详情。
6. 负反馈后卡片立即隐藏，并提供可操作的撤销反馈。
7. 区域选择、独立搜索页、刷新、详情跳转、主操作提示、订单状态跳转和触底加载在原型中可操作。
8. 页面覆盖默认、筛选、刷新、隐藏内容、无更多和失效内容表达。
9. 390×844px 下文字不截断、控件不重叠、底部导航不遮挡信息流。
10. 桌面预览保持手机容器完整，页面层级和图片加载正常。
11. 首页、订单状态滚动后和搜索页截图复核通过，`npm run build` 和 `npm run lint` 通过。
