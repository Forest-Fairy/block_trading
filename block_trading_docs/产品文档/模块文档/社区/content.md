# 社区

## 页面目标

社区页承载围绕共同需求建立关系的社交功能，首期包含购物拼单、出行拼车和娱乐凑伙。用户可以浏览、筛选、发布、参与、分享和管理活动。

## 页面结构

1. 顶部栏：页面标题、搜索和发布入口。
2. 业务分类：购物拼单、出行拼车、娱乐凑伙。
3. 筛选栏：附近、时间、人数、线上/线下和最新发布。
4. 社区列表：统一卡片骨架，根据业务类型展示差异字段。
5. 悬浮发布按钮：根据当前分类预选发布类型。

## 分类设计

### 购物拼单

适用于共同购买、批量优惠或分摊运费。卡片展示商品或服务、单人价格、目标人数、当前人数、截止时间和交付方式。

发布时填写标题、商品来源、目标人数、价格说明、截止时间、交付方式、退款规则和参与须知。

### 出行拼车

适用于共同路线和时间的出行。卡片展示出发地、目的地、出发时间、剩余座位、费用方式和发起人认证状态。

发布时填写出发地、目的地、时间窗口、车辆或乘客身份、人数、费用、行李限制和联系规则。精确联系方式仅对已确认成员开放。

### 娱乐凑伙

适用于游戏组队、桌游、观影和旅游凑人。卡片展示活动类型、线上或地点、开始时间、目标人数、已有人数和参与要求。

发布时选择游戏组队、旅游凑人或其他娱乐，填写主题、时间、地点、人数、成员要求、费用和取消规则。

## 社区详情

- 头部展示类型、标题、状态和分享操作。
- 核心信息区展示时间、地点、费用、人数进度和截止时间。
- 发起人区展示头像、认证信息、历史完成率和举报入口。
- 成员区展示已加入成员及剩余名额；隐私场景只显示脱敏头像。
- 说明区展示详细描述、参与要求和取消规则。
- 底部固定主操作：立即参与、申请加入、管理活动或查看结果。

## 状态模型

```text
草稿 → 审核中 → 招募中 → 已达标 → 进行中 → 已完成
                  ├──────→ 已满员
                  ├──────→ 已取消
                  └──────→ 已超时
```

出行和旅游类内容可配置为“申请加入”，由发起人确认；购物拼单默认即时加入。涉及支付时，参与记录和支付记录分开表达。

## 安全与治理

- 出行、旅游和线下活动必须提供举报、拉黑和紧急联系人提示。
- 不在公开页面展示手机号、车牌号和精确家庭地址。
- 对高风险词、外部交易引导和异常频率发布进行审核。
- 用户退出、活动取消和费用变化必须产生业务通知。

## 页面状态

| 状态 | 页面表现 |
|---|---|
| 无内容 | 提供切换分类、扩大范围和发起活动三个动作 |
| 人数已满 | 主按钮显示已满员，可允许候补 |
| 已超时 | 展示未达标原因和退款或关闭进度 |
| 审核中 | 仅发起人可见，显示预计处理时间 |
| 被拒绝 | 展示可修改项和重新提交入口 |
