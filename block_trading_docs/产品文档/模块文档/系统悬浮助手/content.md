# 系统悬浮助手

## 模块定位

系统悬浮助手是移动端跨页面的统一轻入口，承载建帖、近邻求助和在线客服。它不替代社区首页的信息架构，也不在社区页面新增添加按钮；所有建帖路径都由此入口进入。

## 悬浮球与菜单

- 悬浮球默认位于页面右边缘的中下部。拖动过程实时跟随手指，松手后才吸附到左或右边缘；顶部不能进入状态栏，底部最大位置为底部导航上边框减去悬浮球半径，因此最多只有半个球沉入导航栏视觉层。
- 悬浮球吸附后 2.6 秒无操作自动向边界外收起三分之二，仅露出三分之一。收起态首次点击只恢复完整球体并重置计时；若球体沉入底部导航，同时上移到导航栏上沿之上。第二次点击才打开菜单；系统“减少动态效果”开启时不播放滑入滑出动画。
- 底部导航始终拥有更高层级，避免浮球覆盖导航按钮。存在未完成草稿时，悬浮球使用金黄色发光边框；展开菜单后，存在草稿的功能项显示金黄色圆点。
- 点击完整悬浮球展开四项菜单：发起拼拼贴、我要组队、发起求助、在线客服。浮球在右侧时菜单向左展开，在左侧时向右展开；当浮球靠近顶部时菜单顶部对齐，当浮球靠近底部时菜单底部与底部导航上沿对齐，避免任何菜单项被遮挡。菜单采用淡入，选择任一功能后立即淡出并打开沉浸式聊天。
- 点击菜单外的任意页面区域、滚动页面、拖动浮球或进入任一沉浸式流程时关闭菜单；菜单外点击只关闭菜单，不改变浮球位置和收起状态。所有可点击区域不小于 44px，并提供名称可访问标签。
- 推荐页标题“趣汇”后方设置仅用于原型的预置位。未嵌入时展示虚线圆形框；推荐内容滚动超过 18px 后，预置位固定到与标题一致的壳内坐标，保证仍可拖入归位，回到顶部后恢复标题后方位置。浮球中心进入预置位 56px 容错范围后，须连续 0.5 秒未移动才开始 3 秒计时。计时开始时球体自动对齐预置位中心，并通过两阶段完成归位：第一圈旋转至 360 度并缩小，第二圈旋转至 720 度并完成缩小；完成后隐藏、预置位变为助手按钮，形成嵌入效果。嵌入后按住助手按钮 3 秒，按钮外圈显示加载进度，完成后浮球以弹簧效果从预置位位置弹出并立即接管当前手指继续跟随，松手后才结束拖动，按钮恢复为虚线圆形框。手指重新拖动嵌入中的浮球时，立即取消归位动画并由手指在当前位置继续接管，松手后再按普通拖动规则吸附。弹出后必须先拖离预置位容错区，才能再次触发嵌入；拖动离开容错范围或提前松开长按均取消计时。
- 移动端 Web 的预置按钮与浮球均禁用触摸平移手势，长按弹出后由预置按钮持续转发同一 `pointerId` 的移动坐标；仅该手指的实际松开事件能结束拖动并触发边缘吸附，浏览器手势取消不得导致提前吸附。
- 预置位的 0.5 秒静止判断、3 秒嵌入进度与旋转缩小动画均可中断：期间拖动浮球、用户主动滚动页面，或点击底部导航任一入口，立即取消嵌入、清理计时，并让浮球按当前位置直接吸附到右侧；自动滚动等程序行为不应中断嵌入，滚动和导航原有行为继续执行。

## 建帖流程

| 菜单动作 | 建帖类型 | 机器人首轮引导 | 必填补充方向 |
|---|---|---|---|
| 发起拼拼贴 | 购物拼单、出行拼车 | 一次说清想拼的商品/路线、时间、人数、地点和预算 | 商品与交付，或路线、座位与费用 |
| 我要组队 | 线下组队、线上开黑 | 一次说清活动、时间、地点或平台、人数和要求 | 费用/取消规则，线上最少与最多人数 |
| 发起求助 | 普通求助、紧急求助 | 一次说清需要什么帮助、时间、地点、报酬和最晚响应时间 | 时效性、使用时段、报酬与隐私范围 |

1. 用户先在菜单选择大类，再在聊天上下文中选择明确类型，例如“发起拼拼贴 -> 拼单/拼车”；明确类型写入草稿上下文，随后才请求自然语言描述，不再重复询问类型。选择后提供“返回类型选择”操作。
2. 后端表单构建智能体根据明确类型的字段 schema 解析文本，并以 SSE 增量返回 `{ "form": {}, "force": [] }`、`missingRequiredFields`、`assistantMessage` 与 `confidence`。`form` 仅为建议回填值；`force` 只包含用户在本轮输入中明确要求修改的字段名。
3. 前端只对未手动编辑的字段应用 `form`。当字段已由用户填写且不在 `force` 中时，显示“是否采用”而非覆盖；在 `force` 中时才可覆盖，并保留变更记录。每一轮只追问 1 至 3 个最影响发布的缺失字段。
4. 标准聊天头部并列“返回”和“手动填写”按钮，输入栏左侧不再放编辑按钮。用户在本次会话实际修改类型、输入内容、表单字段或图片后点击返回时，弹窗只询问“是否保存草稿”，并提供“暂不保存”和“保存草稿”；未编辑时直接返回。
5. 字段校验完成后展示“预览帖子”按钮，点击后进入手动填写页，而不是直接发布。手动填写页顶部提供多图上传栏，第一张图标记为封面；无图片时展示浅色随机底色与随机帖子标题，标题使用白色描边。
6. 预览提交前仍执行字段校验、敏感内容治理和场景安全规则，成功后进入社区既有审核流程；模型没有发布权限。

## 求助与客服

- 普通求助按既有会员月度配额校验；紧急求助先展示“如遇人身危险请优先拨打当地紧急电话”的明确提示，再允许创建，避免把平台聊天表达为紧急救援能力。
- 在线客服跳转到独立客服聊天会话，支持文本和语音输入。语音按钮按住开始录音，向上滑动取消，正常松开后转写到输入框供用户确认，不自动发送。
- 建帖对话也复用文本和语音输入；语音仅是输入方式，不影响字段来源、校验或审计标识。

## 原型交互说明

- 原型用固定时序模拟后端流式回填：发送自然语言后，以 `{ form, force }` 逐项回填草稿，随后机器人展示下一轮缺失字段问题与“是否采用”状态。
- 原型覆盖右侧展开菜单、左侧展开菜单、2.6 秒自动收起、实时拖动、顶部/底部菜单对齐、草稿金色状态、推荐页预置位嵌入与长按弹出、客服按住语音、智能建帖、预览手动填写、多图封面与取消创建。

## 验收标准

1. 右、左边缘各自菜单朝页面内侧展开，且菜单不会遮挡浮球露出的可点击区域；靠近顶部/底部时菜单对应对齐并完整可见。
2. 停留 2.6 秒后浮球只露出约三分之一；拖动过程实时跟手，松手会吸附到最近侧，底部最多沉入导航栏半径高度。
3. 有未完成草稿时球体为金黄色发光边框，打开菜单后相应功能项显示圆点。
4. 菜单选择后先淡出，再进入对应聊天；建帖经过明确类型选择和上下文回退后，聊天底部始终有文本输入与语音按钮。
5. 一段自然语言输入能以 `{ form, force }` 逐项回填草稿、提示字段采用与追问缺失必填项；手动填写、保存草稿确认和取消创建均可达。
6. 建帖完成后可进入预览手动填写，多图上传时第一张明确为封面；无图时浅色随机背景与白色描边标题可见。
7. 390×844px 下菜单、聊天输入栏、悬浮球与底部导航无不合理重叠，紧急求助安全提示可见。
8. 推荐页预置位的浮球容错停留、3 秒环形进度、嵌入按钮与 3 秒长按弹出均可完成；提前移出或松手时不改变嵌入状态。
