# 趣汇帖子领域实体设计

## 数据库基准

- 以 Oracle 为准，但只定义实体字段的逻辑类型、长度、精度、必填性和关联关系，不绑定 DDL、序列、分区或触发器。
- 主键使用 `NUMBER(19)`，Java 映射为 `Long`；枚举使用 `VARCHAR2(32)`。
- 金额使用最小货币单位 `NUMBER(19)`，Java 映射为 `Long`；例如 `8600` 表示 ¥86.00。
- 数量使用 `NUMBER(10,2)`，人数使用 `NUMBER(5)`，经纬度使用 `NUMBER(10,7)`，业务时间使用 `TIMESTAMP(6)`。

## qh_post：帖子主实体

| 字段 | 逻辑类型 | 非空 | 说明 |
|---|---|---|---|
| `id` | `NUMBER(19)` | 是 | 主键。 |
| `author_id` | `NUMBER(19)` | 是 | 发起人。 |
| `post_type` | `VARCHAR2(32)` | 是 | `GROUP_BUY`、`CARPOOL`、`OFFLINE_TEAM`、`ONLINE_TEAM`、`NEIGHBOR_HELP`。 |
| `status` | `VARCHAR2(32)` | 是 | 正式帖子状态：审核中、审核被拒、招募中、已达标、进行中、已完成、已满员、已取消、已超时。草稿不写入本表。 |
| `visibility_scope` | `VARCHAR2(16)` | 是 | `PUBLIC` 或 `CAMPUS`。 |
| `campus_id` | `NUMBER(19)` | 条件 | 同校可见时必填。 |
| `join_mode` | `VARCHAR2(16)` | 是 | `DIRECT` 或 `APPLICATION`。 |
| `title` | `VARCHAR2(60 CHAR)` | 是 | 2-60 字。 |
| `content` | `CLOB` | 否 | 补充说明；近邻互助必填。 |
| `current_participants` | `NUMBER(5)` | 是 | 当前确认参与人数。 |
| `min_participants` | `NUMBER(5)` | 是 | 最少人数。 |
| `max_participants` | `NUMBER(5)` | 是 | 最多人数。 |
| `primary_occurs_at` | `TIMESTAMP(6)` | 是 | 开始、出发或需求时间，用于跨类型排序。 |
| `signup_deadline_at` | `TIMESTAMP(6)` | 是 | 报名、下单或最晚响应时间。 |
| `published_at` | `TIMESTAMP(6)` | 否 | 审核发布成功时写入。 |
| `version` | `NUMBER(10)` | 是 | 乐观锁版本。 |
| `created_at`、`updated_at` | `TIMESTAMP(6)` | 是 | 审计时间。 |
| `deleted` | `CHAR(1)` | 是 | `N/Y` 逻辑删除。 |

## qh_post_draft：帖子草稿实体

| 字段 | Oracle 类型 | 必填 | 说明 |
|---|---|---|---|
| `id`、`author_id` | `NUMBER(19)` | 是 | 主键和草稿所有者。 |
| `source_post_id` | `NUMBER(19)` | 否 | 审核被拒后返修时关联原正式帖子；首次创建为空。 |
| `post_type` | `VARCHAR2(32 CHAR)` | 否 | 已选择的帖子类型；类型选择前允许为空。 |
| `draft_source` | `VARCHAR2(24 CHAR)` | 是 | `COMMUNITY_FORM`、`ASSISTANT_TEXT`、`ASSISTANT_VOICE` 等来源。 |
| `draft_payload` | `CLOB` | 是 | 结构化草稿载荷，保存已填字段、助手建议、未确认地点和表单版本；不作为正式查询字段。 |
| `version` | `NUMBER(10)` | 是 | 乐观锁版本，防止多端覆盖草稿。 |
| `expires_at`、`created_at`、`updated_at` | `TIMESTAMP(6)` | `expires_at` 否，其余是 | 过期清理与审计时间。 |

- 草稿不能直接使用 `qh_post(status='DRAFT')`：原型允许在主题、时间、人数和五类扩展字段未齐时保存，而正式帖子及扩展实体的非空约束用于保证发布后可筛选、可参与和可通知。
- 发布时由应用服务执行字段校验并将草稿转换为 `qh_post`、一张类型扩展表以及地点、媒体等从表；正式帖子初始状态为审核中。转换成功后保留草稿一段可配置时间用于恢复与问题排查，之后按保留策略清理。
- 审核被拒后正式帖子保留 `REVIEW_REJECTED` 状态和拒绝原因；用户修改时创建带 `source_post_id` 的独立草稿。重新提交后用乐观锁更新同一正式帖子聚合并重新进入审核中，不把正式帖子改回草稿状态，也不创建失去关联的新帖子。

## qh_post_location：地点实体

一帖可有公开区域、收货、上车、集合或需求地点等多个角色。精确地点通过 `visibility_level` 限制为已确认成员可见。

| 字段 | 逻辑类型 | 非空 | 说明 |
|---|---|---|---|
| `id`、`post_id` | `NUMBER(19)` | 是 | 主键、关联帖子。 |
| `location_role` | `VARCHAR2(24)` | 是 | `PUBLIC_AREA`、`PICKUP`、`MEETING`、`DELIVERY`、`NEED` 等。 |
| `visibility_level` | `VARCHAR2(24)` | 是 | `PUBLIC`、`CONFIRMED_MEMBER`、`OWNER_ONLY`。 |
| `district_code` | `VARCHAR2(32)` | 否 | 行政区编码。 |
| `district_name` | `VARCHAR2(64 CHAR)` | 是 | 默认公开展示市区。 |
| `street_name` | `VARCHAR2(96 CHAR)` | 否 | 市区缺失时展示街道。 |
| `display_name` | `VARCHAR2(160 CHAR)` | 否 | 精确点位或文字描述。 |
| `latitude`、`longitude` | `NUMBER(10,7)` | 否 | 距离计算和位置筛选。 |

## qh_post_participant：参与实体

| 字段 | 逻辑类型 | 非空 | 说明 |
|---|---|---|---|
| `id`、`post_id`、`user_id` | `NUMBER(19)` | 是 | 主键、帖子和用户；`post_id + user_id` 唯一。 |
| `join_status` | `VARCHAR2(24)` | 是 | 申请中、已确认、已拒绝、已退出、候补。 |
| `payment_status` | `VARCHAR2(24)` | 是 | 不需要、待支付、已支付、已退款；与参与状态独立。 |

| `applied_at`、`confirmed_at`、`exited_at` | `TIMESTAMP(6)` | 条件 | 对应状态发生时间。 |

| 字段 | 逻辑类型 | 非空 | 说明 |
|---|---|---|---|
| `id`、`post_id` | `NUMBER(19)` | 是 | 主键和关联帖子。 |
| `from_status`、`to_status` | `VARCHAR2(32)` | `to_status` 是 | 前后正式帖子状态；创建审核记录时前状态可空。 |

## 关键关系与校验

- 一条 `qh_post` 只允许关联一张与 `post_type` 匹配的类型扩展实体；地点、媒体、参与、字段变更日志和状态流水为一对多。
- 人数满足 `1 <= min_participants <= max_participants`；确认人数达到上限后禁止新增确认参与。
- 即时互助只填 `needed_at`，时段互助只填开始/结束时间；两种情形均应早于最晚响应时间。
- 推荐索引基线：帖子按状态、类型和主时间；可见范围按范围、校园和发布时间；参与记录按用户、参与状态和更新时间。空间索引由 Oracle Spatial 部署策略决定。
